## 1. 本轮结论与用户边界

橙子重构必须以既有业务为主体：账号与云管家映射、授权素材领取及校验、个人选用和备注、创作项目、配音与额度、Agent任务验收和成长记录都不能被“换成OpenFilm编辑器”所替代。保留的是业务目的、数据含义与可核验的约束，不代表原样迁移演示身份、旧时间轴或全部Python实现。

Ethan已明确：橙子内的工程与成品仅本人账号可看，列表、直接访问和下载均需校验归属，不只隐藏小组浏览入口；同一小组仍共享历史组合去重判断。上传云管家后的可见性属于云管家权限边界，不反向开放橙子工程，也不等于公开发布。个人工程可见范围与源素材的使用权不同：资料中心应按本人绑定云账号的授权展示素材，不应擅自缩成“仅本人上传的素材”。

源码复核阶段由账号/云映射、创作/Agent、素材管线三个审视方向交叉核对；主审复查关键组合根、身份入口、归档与版本逻辑。只读源码、测试文本与文档，未运行项目或测试、未安装依赖、未访问真实IAM/云管家、未读取运行凭据。用户编写的[05业务全景](../05_业务拓扑与逻辑全景.md)保留原状，下文另列实现纠偏。

交接包明确不含生产绑定库、业务数据库、真实素材、统一账号中心源码或运行凭据；39位员工、199个原片等是交接记录，不是本轮验证的新产品容量或正式用户上限。[交接范围](../history/README.md)、[历史验证与限制](../history/README.md)

已确认的身份边界：橙子本来具有自己的登录体系，智尚只是第三方素材库；新版继续独立橙子账号、绑定本人云管家，不以智尚登录替代橙子认证；旧百橙账号及历史数据要迁移承接，不能串号或丢失。当前交付主线是可编辑剪映草稿、云管家上传和直接视频导出。以下第2节描述旧源码现状，不是继续采用旧IAM作为新版登录入口的建议；三条新链路也尚未因此成为已实现能力。

## 2. 最关键断点：两套身份和素材库尚未贯通

### 2.1 真实云素材链

网页登录Cookie → 百橙IAM账号ID及创作中心准入 → 当前有效云管家绑定 → 供应商复核绑定账号 → 按本人云账号查询、预览、领取视频和解析。

桌面通过配对取得设备会话，再回到同一IAM准入检查。网关以IAM账号ID查询启用绑定，匹配云登录名、account_key、姓名和启用状态；公司范围由当前网关配置决定，不能把姓名当持久身份，也不能用管理员权限替代员工权限。[central/service.py:45–103](D:/dev/orange-legacy-primary-20261107/central/service.py#L45)

真实桌面云素材在cloud-materials下按IAM账号ID和云视频ID分区。下载前、收包时、最终入库前核对账号；列表与取文件依赖当前中央身份，现状不是已经验证的长期完全离线素材库。[cloud_bundle.py:43–98](D:/dev/orange-legacy-primary-20261107/orange/cloud_bundle.py#L43)、[cloud_bundle.py:130–170](D:/dev/orange-legacy-primary-20261107/orange/cloud_bundle.py#L130)

## 3. 账号与云管家对应必须独立建模

### 3.2 建议统一的身份语义

以下是候选契约含义，不是已确定的表名、字段全集或数据库变更：

| 概念 | 职责 | 不能混用 |
| --- | --- | --- |
| 橙子个人主体 ownerUserId | 工程、成品、个人备注/选用、Agent记录的稳定归属 | 演示角色、显示姓名、云account_key |
| 登录身份 issuer + subject | 将具体认证提供方映射到橙子个人主体；保留既有IAM来源映射 | 新认证系统ID直接冒充旧IAM账号或供应商账号 |
| 小组去重范围 | 共享组合判重与并发预占；保留创建人用于审计 | 不等于工程所有者，也不授予组员读取工程的权限 |
| 云账号绑定与绑定版本 | 连接本人主体、供应商、公司范围、外部账号与有效状态 | 企业凭据不能充当员工身份；客户端不能自报绑定即可信 |
| 供应商素材引用 | 在明确供应商/公司范围内映射云videoId到内部素材及文件版本 | 云videoId、assetId、文件hash、段落ID不能当同一个字段 |
| 上传/下载任务身份快照 | 留发起者、有效绑定引用/版本、目标范围、对应来源版本和外部回执 | 不把供应商密钥或短期下载URL复制进日志/任务明文 |

任务开始和外部提交前应核对身份及绑定版本，换账号、换绑或撤权时不得把旧任务结果落到新账号。真正的上行上传另建可审计流程，保留提交、受理、云端确认与本地可用的不同状态；上传可见性按云端规则核对，不自动扩大橙子内可见范围。

新版采用独立橙子账号、再绑定本人云管家已获Ethan确认。旧百橙身份保留为迁移来源映射，而非新版唯一登录前提。认证实现、本人绑定证明、绑定基数、换绑管理、退出小组后的留存，以及上传接口如何表达实际目标账号和可见范围仍待确定。不得按姓名、邮箱相同或文件目录名自动关联。

### 3.3 旧账号与历史数据的迁移约束

已确认的验收目标是不串号、不丢失旧账号关联及历史数据；这不是本轮已完成迁移或已验证零丢失的声明。交接包没有真实业务库与生产绑定库，必须在明确授权和范围后先取得清单，不能将源码快照当作完整数据备份。

建议采用以下约束，具体迁移方法另行评审：

1. 为旧身份保留来源系统与稳定账号ID到橙子个人主体的明确映射，核验本人归属及云绑定；不要把旧角色名、同名/同邮箱、当前登录者或供应商account_key直接当个人主键。
2. 先盘点和保全旧数据，再形成可审阅的迁移清单及异常清单。工程、成品、素材文件/版本、领取与备注、Agent轮次、绑定记录等按实际存在情况登记；未交接的数据明确列为缺口。
3. 保留原始来源记录、旧ID与引用关系；已核实数据才映射给本人，无法证明归属的employee演示数据或冲突记录隔离保留，不能自动认领，也不能直接删除。
4. 迁移后核对数量、文件校验值、所有者、关联引用、状态和代表性可编辑/可播放结果。纯条数一致不足以证明无串号或可用性，重复执行也不能重复建立账号或产物。
5. 准备可恢复副本及恢复演练，不在核对通过前覆盖或删除唯一旧副本。旧数据的迁移映射不自动恢复已撤销的素材权限，不搬用旧会话充当新认证；供应商绑定需按当前状态复验。
6. 小组去重历史与个人项目所有权分别承接；旧成片缺少实际剪辑方案时保留它及证据缺口，不伪造组合指纹或声称完整恢复所有历史判重能力。

### 3.4 三条交付链路

Ethan已明确当前要打通真实可编辑剪映草稿、上传云管家、直接导出视频，而不是仅保留旧MP4和通用ZIP。对应能力可由用户按需选择，不强制每次同时发生。

建议同一输入修订对应独立的成片产物、剪映草稿产物和云端入库任务，分别保留来源、目标账号/预设、处理状态及结果证据。草稿按指定剪映版本打开/修改/保存/重开验收；视频按720p/1080p正式支持集合验收；云上传以实际入库确认验收，不能以HTTP受理代替。上传后的可见范围仍由云端权限核对，不反向改变橙子工程的个人归属。

C30已确认首版云管家上传包含素材切片和最终成片。两类都先确认内容及对应标签，再上传到本人已核验绑定的账号，不自动公开。该确认不扩展为上传整个film工程、剪映草稿工程包或全部本地素材，也不强制所有本地成果上传。

工程建议：上传对象类型与标签分开；切片引用素材版本，成片引用实际产物和来源工程修订。确认记录关联实际文件版本、标签快照、本人绑定版本及可见范围；更换内容、标签或目标账号后需重新确认，不用一次批准覆盖后续任意变化。C31已确认清单核对、逐条修正标签、勾选多条后一次确认上传。供应商文档已列出分类、视频标签、个人标签与公共标签字典接口；本公司真实字典与权限尚未实测，橙子语义映射、必填与继承规则、确认快照变更校验及恢复细则仍待D21收敛。

批量确认只覆盖明确勾选的条目及其确认内容，不包括未选项或后续新增项。工程建议将确认时的文件版本、标签与本人绑定账号冻结为逐项记录，并保留逐条执行结果；批量确认不是一次无法区分部分成功的总状态，也不等于所有文件同时上传。

本地导出、文件入库、标签写入与可见范围核验分别有结果。供应商已受理不等于入库完成；文件成功但标签未完成时，应对账补齐而非盲目重传。本次产品决定不代表已验证所有接口支持这些字段；云端范围无法控制或默认值不明时，不静默放宽授权或公开。

### 3.5 供应商接口研究补充

[04接口能力与系统协同](04_智尚接口能力与系统协同.md)区分供应商文档、旧代码和实际联调证据。旧橙子仅装配公司认证、账号列表、视频列表、原片地址四类端点；供应商文档中存在的标签、分类、导入和状态查询不能视作旧代码已经实现。

## 6. 重构后的职责关系建议

- Orange领域层：个人主体、云绑定、素材授权、审核、领取、个人工作库、配音与额度、Agent任务及成长、项目归属、批量任务与审计。主界面继续承载橙子的产品任务。
- 统一素材中心：管理原片/文件版本、解析修订、候选片段、人审状态、使用授权、位置与个人选用；正式可用本地素材可以不上传。
- 素材加工：ASR/选片/切片/标签生成候选；人工确认内容与范围后转正式素材，上传智尚是独立动作。首版也支持最终成片上传，两类均确认内容和标签、上传本人绑定账号，不自动公开。
- Fission：按文件夹组顺序/配方规划候选、组内共享判重、冻结实际方案、执行批量输出；重复重组、集中二编、真实计数和主动结束沿用C20–C24。
- film：负责人工和Agent可编辑的工程修订，不承接企业凭据、供应商绑定或审核权限。Fission进入后，其冻结方案保留来源，后续内容以对应编辑修订为权威。
- 导出适配：绑定输入修订、素材来源和导出预设，分别交付MP4/真实剪映草稿及兼容报告；不要求全部批量结果先打开编辑器。
- 云账号适配：独立橙子账号绑定本人云管家，素材查询、预览和下载按该绑定授权执行，不能用服务身份扩大可访问素材范围；上传的技术身份和目标归属表达按D19与实际接口验证，不能因服务端持有企业凭据就改为无范围的管理员操作。记录外部回执，保留新旧身份与供应商账号的显式映射，不污染领域ID。

对现有代码的处理不宜简单“全保留”或“全丢弃”。建议先建立业务编号、旧入口、旧数据/状态、不变量、目标模块、迁移方式和验收证据的一一对应；明确哪些实现替换、哪些能力暂缓，不能因编辑基座变化悄悄砍掉业务。
