## 既有规则、业务细节与历史证据


**橙子是业务主体，film（基于上游OpenFilm）是创作中心的编辑模块，Fission 是批量创作引擎，素材中心是共同资源入口；素材加工负责产生经人审可用的素材，剪映草稿与成品视频是交付物，智尚是独立账号绑定的第三方素材库。** 它们不是六个各自拥有账号、素材表和任务系统的产品。

本稿区分业务/技术方向确认、工程基线和待验证事项；C87已确认核心选型，不代表具体版本、集成或实施已验收。本轮仅整理文档，不改业务代码、不迁移数据。按 Ethan 最新要求，智尚账号问题及相关接口验证挂起，不扩大账号范围，也不继续接口调用；云上传仍保留在首版目标中，不能因此标记为已联通。

C41确定产品入口为素材工厂、超级混剪、创作中心、草稿箱；分别承接素材加工、Fission、film及可编辑工程留存，C88明确film产品名，上游来源及契约不另起一套。C48要求本重构版与旧线上方案独立，开发、测试和未来发布不得隐式影响现网；本轮仅改方案文档。

文档权威、契约冻结和开发Agent协作统一见[09规范](09_文档权威与多Agent开发协作规范.md)；本稿定义逻辑架构，C87技术方向及物理目录/依赖以[13技术架构与目录依赖基线](13_技术架构与目录依赖基线.md)统一登记；未验证的运行时行为不写成已通过。

## 2. 整体拓扑与职责关系

以下是落实已确认方向的工程建议，不是已经建成的系统。

~~~text
橙子 Windows 客户端：第一方账号、业务页面、审核清单、任务与结果中心
│
├─ 统一素材中心：来源 / 版本 / 本地与云端位置 / 权限 / 标签 / 可用状态
│    ├─ 授权智尚素材 → 按需领取并校验 → 本地可用资源
│    └─ 素材加工 → 候选切片与标签 → 人工审核 → 可用本地素材
│
├─ Fission：有序场景组 + 配方 + 固定素材版本 → 冻结实际剪辑方案
│    ├─ 在线查重与预占 → 直接导出视频或剪映草稿
│    └─ 导入 film → 工程修订 → 人工 / Agent 编辑
│                                └─ 冻结待交付修订 → 对应判重 → 导出
│
├─ 交付中心：成品视频 / 剪映草稿包 / 文件与依赖校验 / 逐项结果
│    └─ 素材切片、已审核AI补充素材、最终视频 → 上传清单 → 人工勾选确认 → 上传与对账
│
└─ 共同底座：稳定身份、契约、授权、持久任务、资源调度、追踪与审计
          │
          └─ 橙子可信服务：第一方权限、同组原子预占、绑定、批准与云对接
                      └─ 智尚适配器 → 第三方素材与标签 / 异步导入
~~~

图中的“对应判重”仅针对Fission批次及用于补齐原批的二次编辑；C67明确独立创作中心成果不进入组内去重，不将全部本地编辑/导出锁成在线准入。入口变化不能删除既有Fission历史。

### 六个核心板块

| 板块 | 负责什么 | 交给下游什么 | 明确不负责什么 |
| --- | --- | --- | --- |
| 素材加工 | 原片分析、ASR、候选区间/评分、切片生成、摘要和标签建议、人审 | 有来源血缘的素材版本、分析结果及审核修订 | AI建议直接发布；把模型分数当人审通过 |
| 素材中心 | 统一检索、领取校验、个人使用记录；管理版本、位置、权限与标签 | 明确版本及可访问文件引用、权利状态、标签快照 | 自动把所有本地文件上传；把待审核项混入正式选材池 |
| Fission | 按有序组和配方批量规划，重组及批次管理 | 每条结果的实际选材、区间、顺序、音轨及编辑决策 | 仅凭随机种子还原工程；重试时打乱叙事组顺序 |
| film | 人工/Agent编辑、预览、工程修订、撤销与导出请求 | 某次不可变工程修订的交付快照 | 另一套橙子账号/素材库；双向自动改写原 Fission 方案 |

| 云上传 | 清单、人审批准、受控文件交付、异步入库与逐项对账 | 上传结果、外部资源映射、标签与归属/可见性核对结果 | 自动公开或投放；把“已提交”当“已成功” |

统一素材中心是资源目录和状态视图，不要求所有字节集中到一个目录或云桶。一个素材可以同时有本地文件、代理文件和云端映射；每个文件表示仍要区分字节校验值与可用性。最终视频也可在素材中心的“成片”视图通过产物引用展示，不另造无血缘副本；是否自动成为下一轮可抽取素材尚未确认。

## 3. 业务闭环一 素材加工与素材入库

### 建议的操作顺序

1. 从本人实际获授权的智尚素材或允许使用的本地原片进入素材中心，登记稳定资源身份、来源和使用限制；按需取得并验证文件。
2. 加工任务引用确定的源版本。ASR、场景/高光候选、模型评分与 LLM 摘要产生分析修订，不覆盖人工标签。Jev 类选片方法是候选技术，不是已确认算法或已验收准确率。
3. 用户核对候选区间、内容和标签；拒绝、调整、确认分别记录。区间或源版本改变后，不能沿用对旧内容的审核。
4. 生成并校验切片文件，建立从原片区间到新片段的血缘。实现可预生成供人审，但“人工已确认”和“文件已就绪”必须同时满足后，才能成为正式可选素材。
5. 正式素材立刻可供 Fission/film 使用；上传不是本地可用的前提。加工失败或文件丢失不因人审通过而被显示为可用。
6. 用户可另行把切片加入上传清单；上传批准与素材审核不是同一个动作。未经上传确认，不因标签齐全或云账号已绑定就启动上传。
7. 一旦取得可靠的逐项云端资源回执，先保存外部ID与既有素材的关联及当前核验状态，不等所有标签/权限核验完成才落映射；全部要求核验通过后再标完整成功。云端转码产生不同字节时，保留独立校验信息，不覆盖本地原始文件的hash。

读取/领取权不自动等于加工、成片导出、打包原片到剪映或再次上传权。建议在加工准入和各交付边界按动作核验使用权，派生切片、代理和成片保留来源限制；人工审核和来源血缘都不能创造权限。哪些限制由智尚返回、哪些需企业约定及如何继承，纳入D07/D09，不能把“本地可用”当作全部外发授权。

本地闭环是“取得素材 → 加工人审 → 创作 → 本地交付”；云端闭环是在明确确认后加上“入库 → 回写映射 → 在实际授权范围内再次检索使用”。二者可以独立成立。

### AI补充素材支路

C60已确认首版补充来源：产品展示/人物/场景镜头需求 → 实际生成候选 → 人工审核 → 文件及当前使用权核验 → 素材中心 → 超级混剪或创作中心。云管家素材不被替代；生成完成不等于审核通过，通过后可本地使用，不以先上传为前提。选择上传时另行进入本人上传清单确认，不因生成、人审或加入素材中心而自动上传/公开。

工程建议复用素材工厂审核入口及公共AI、Job、积分与媒体校验能力；生成与原片分析是不同任务，不伪造原片切片血缘。保留需求/获准参考输入、模型调用、实际输出版本、人审及使用关联；新输出版本重新人审，待审或拒绝项不向两创作入口提供正式选材。模型/输入方式、效果一致性、成本/耗时及异步未知结果恢复仍待验证，入口布局不作为已确认页面设计。

### 真人录制结果处理支路

C61已确认录制成果支持ASR识别、编辑、LLM分析建议和JEV评分，并可供film作为素材使用、Fission选择复用。工程建议复用“真实录制文件 → 分析与人工编辑 → 人工核对 → 素材中心 → 两入口”的路径，不另造录制专库，也不要求每份既有文件先建派单需求。C62已确认同时支持纯音频和真人口播视频，前者作配音素材、后者作视频素材，均经人工审核进入素材中心供两入口复用；C75已追加确认应用内录音、重录和落库；C82排除应用内摄像，派单/通知/回传优先复用云管家并按本人绑定同步，接口仍按D26验证，不把已确认录音再次列为未获准。

原录制、转写/人工改稿、媒体编辑修订及评分输入分别关联；改文字不自动改变真人原声。LLM建议和JEV评分可辅助筛选，不代替人审、不新增硬分数门槛；分析与评分须对应实际版本。两入口引用相同素材域的可用版本，不将音频当镜头或占位任务当文件；本地处理和复用不要求先上传。云上传仍另确认，纯音频直传智尚能力未验证，不借此扩展接口承诺；断网仅使需在线模型的动作等待，不把所有有效本地编辑一律禁用。

## 4. 业务闭环二 Fission 批量创作

1. 用户导入素材根目录。按数字序号形成有序场景组，例如1开场、2产品、3讲解；组序是业务顺序，不是文件系统偶然返回顺序，也不由云标签排序替代。重号、缺号及非规范名称的处理仍需规则和提示。
2. 配方记录每组候选和抽取规则；实际规划再解析出每条结果的素材版本、源区间、时间线、配音/BGM/字幕等，形成不可变冻结方案。不能把配方、随机种子或路径列表当成完整编辑方案。
3. 方案确定后计算规范化内容组合指纹，在线到同组历史账本查询并原子预占。这里是“渲染之前知道是否重复”，不是在选材和有效参数尚未确定时就知道最终结果。
4. 重复则在既定组序内自动重组；达到约定预算仍不足，汇总为待二次编辑清单。只保存工程或点击“深度编辑”不算新视频；实际内容改变且重新通过查重后才可交付。
5. 无须编辑的方案可以直接导出视频或剪映草稿。需要编辑的方案导入 film，不要求先渲染一份MP4。预占只对应原内容，编辑后的内容需重新检查；如何释放旧占位、续期和失败回收仍需 D16/D17 决定。
6. 每条交付单独执行、验证与记录。同一结果的重试不产生新成功数；重试复用原方案，不能悄悄换一套内容。自动重组属于规划阶段，不是失败渲染的随机重试。
7. C64确认用户主动结束时停止派发并直接停止在途处理，保留实际完成。目标100、成功80显示80/100，未完成不计。工程设计取消/完成竞态和迟到对账，不默认允许在途跑完；C83已确认重做与关联补充批次两种选择均提供，历史和旧结果不清除。

### 多出口与去重历史的补充建议

- 一条结果要关联不可变的结果修订，所有用于满足这次交付的出口都指向该修订。修改前的视频和修改后的草稿不能混合凑成一次完成；旧产物和旧成功证据保留，编辑后重新判重，不继承旧方案的准入。
- “组合已生成并进入历史”与后续视频/剪映/上传操作的状态分开。C44允许生成后再选、重开选择或单独选择出口，不要求预选一组必需出口；新增交付动作或某出口失败不自动释放已有合格成果的组合历史。具体历史登记事件仍由D17/D20结合C40验证。
- C40已确认离线续跑：渲染前仍按C21联网准入；已准入且依赖齐全的条目断网继续本地执行、校验并完成交付，成功事实持久保存，联网后补登记。不能仅因缺少终态云回执扣留合格本地产物，也不能让未获准的新组合绕过去重；详见第7.3节。

### 三种哈希不能混为一谈

- 源文件SHA256用于字节识别和完整性，首次稳定版本算一次并缓存；不是业务主键或授权凭证。
- 内容组合指纹在实际方案确定后、渲染前计算，保留顺序、区间、有效编辑和音轨；不以批次号、用户名、文件路径等制造“新内容”。不同用户引用同一内容时，不能因内部资源ID不同就绕过共享去重。
- 成品文件SHA256在导出后用于文件和上传核对，不能用于渲染前判重。

不枚举所有可能组合入库，不每批下载全部历史、不每次重算全库文件。仅对实际候选作有界尝试、对准入/成功结果留账。命中去重只返回必要结果，不暴露其他组员的工程、素材地址或成品。具体并发、索引规模、归档和查询策略须测量；C58业务记录不删除，不能承诺没有数据库压力。详细边界见[历史组合去重与容量评估](02_历史组合去重与容量评估.md)。

## 5. 业务闭环三 film 编辑与剪映移交

**建议采用一个编辑权威，不维护两条可随意互相覆盖的时间线。**

- Fission 冻结方案是不可变来源事实。导入 film 时建立工程及首个修订，记录来源方案与导入适配器版本。
- 导入成功后，工程修订成为编辑权威。原方案不会随着拖动镜头被反向改写；再次导入应明确新建或显式操作，不覆盖用户当前编辑。
- OpenFilm 原生工程格式与橙子共享交付模型之间用版本化适配层隔离；不预先要求重写 OpenFilm 全部工程结构，也不把全部原生字段扩散给Fission。
- C37/C45已定人工决策、Agent执行、审核审查，允许同一人完成；Agent按明确任务范围执行，不能自审放行。人工和Agent提交仍检查期望修订，过期变更不得覆盖当前编辑；具体提交/撤销机制由工程设计。C42不增加强制创作单或单商品/必备镜头门槛，仅执行用户自选配方和明确要求。
- Agent按C56请求批准/全权限模式执行选片、排序、字幕和配音编辑及自动检查；素材审核、云上传、知识正式沉淀和团队共享仍由人最终确认。执行委托不能提升本人或素材/IP权限，也不默认授权改账号绑定。
- 导出锁定具体工程修订；用户继续编辑不改变已经导出的文件。工程保存、视频导出和剪映移交是三个不同结果。

### 草稿箱的保存与后续批量处理

**已确认C32**：存入草稿箱后仍可编辑镜头、字幕和配音，保留工程、相关素材和标签；后续可批量导出视频/剪映草稿，或核对内容与标签后确认上传本人绑定的云管家账号。它不是只保留MP4的待上传列表，也不是已经生成的剪映草稿包。保存草稿不代表授权上传或公开。

工程落地建议：

1. 草稿沿用同一橙子工程及其修订，关联素材版本、字幕/配音结构、依赖清单、标签修订和已有成品；不为草稿、素材中心、上传清单重复建立互不相认的工程身份。
2. 保存后关闭并重开，应能恢复相应修订及依赖。素材保留不能只有一个可能失效的临时路径或下载URL；建议受管缓存和引用保护，避免普通清理误删活跃草稿依赖，也不必为100条草稿重复复制100份相同素材。具体缓存、保留期和磁盘不足策略待定。
3. 建议支持未渲染成最终视频时保存工程。已有成品则关联具体产物与来源修订，之后编辑不会悄悄改写旧视频。若只有外部合成MP4，仍只能作为视频片段编辑，不能据此承诺恢复原始字幕/音轨分层。
4. 后续批量操作针对用户选中的草稿及明确修订。导出视频走生成与校验；导出剪映草稿走格式适配与依赖检查；上传则准备可核对的视频并进入人审清单，不上传整个橙子工程。
5. 草稿保存进度、视频/剪映导出进度、云端上传进度分别展示；保存工程不计入原视频生成目标的完成数，后续补导出或上传也不自动当作新创作重复计数。具体组合任务成功口径仍属D20。

C33/C34已确认清单修改同步草稿的待提交标签、云管家是正式标签唯一真源。C38已定换机不自动转移本地资产；新设备没有实际文件时不能将旧机路径标为可用，工程也不能只凭云端媒体记录重建原编辑结构。C57已定撤权后对应账户不可见、不可再请求；工程需验证缓存/历史引用拦截、离线传播、待提交修改重核及批量处理中途编辑；显式备份/迁移不等于默认云同步。完整工程留存不自动授予额外使用权，也不等于已经实现或通过兼容测试。

### 生成后选择交付

C44确认：生成的工程/成果保留在草稿箱，用户可选导出视频、剪映草稿或确认上传；未选而关闭出口弹窗，不丢结果、不自动上传。可从草稿箱/结果卡重新打开选择，也可从单独入口操作；批量操作沿用C32。

工程建议：生成内容与后续交付Job分开；再次打开弹窗不是重新生成。已有符合所选修订和规格的产物可复用，若只有未渲染工程则由所选动作准备产物；单选云上传可先本地生成可核对视频，再由用户确认上传，不要求另点本地导出；选择剪映不强制先渲染MP4；两者都保留各自状态，工程保存不算视频生成成功。每个出口引用固定修订，后选出口不改变素材归属，不重复累计同一内容的原生成数。C65明确合格剪映单出口完成进入成功历史、未完成不交付；视频/剪映按类型计数。C66纯编码/分辨率重导出不增加混剪内容成功数；C73普通导出无模型使用不收模型积分。具体入口布局和产物复用由工程冻结。

## 6. 业务闭环四 人审清单与云上传

C46明确绑定属于橙子账号，本地编辑/生成/导出不依赖智尚绑定。云端操作才读取本人绑定并保存目标快照，防止换绑后误投；这不把绑定归属任务。每个用户的本地/云端资产与任务按个人主体隔离；统一素材中心不是跨用户合库。

C45允许本人完成核对与确认，不强制另找审核员。用户说明云管家后续仍有审核，但其工作流/API未验证；入库受理、入库完成与外部审核通过不可混成一个状态。以下顺序兼顾 C30/C31 和已读供应商文档，真实字段与权限仍待验证：

1. 切片、审核通过的AI补充素材或最终视频进入清单，显示内容、当前标签、目标本人绑定及拟用可见范围。用户逐条修正，勾选明确条目。
2. 一次确认形成不可变批准快照，包含选中项、确切文件版本、资源类型/分类上下文、标签及映射修订、个人标签所属账号、绑定版本和批准的范围。新增项、改文件、改标签或换绑定不能静默进入旧批准。
3. 可信服务再次校验本人身份、当前绑定与权限、批准快照和供应商限制。不信任客户端随意提供的外部账号标识。绑定未解决时只阻断相应第三方动作，不退出橙子账号。
4. 智尚文档的导入是拉取可访问URL，不能给它本地磁盘路径。需经用户确认的受控临时文件交付方式，具体存储、有效期、清理和费用尚待选型。
5. 一次业务批准可拆成多次供应商请求；文档导入每请求最多50条、每视频最多10个二级标签，不等于50路并发或整批事务。执行前按适用分类/类型验证必填和有效标签，真实公司字典目前未知。
6. 分开记录橙子上传任务、供应商导入请求、每条外部结果。请求受理后继续逐项对账；响应丢失则进入结果未知，不盲目重提，thirdId不能当已证明的幂等保障。
7. 仅确认文件、归属、标签和批准范围符合约定后展示完整成功；某部分无法证明时展示对应待核对或失败状态，不用一个绿色勾掩盖。部分成功保留结果，失败条目可在仍有效的批准下按规则重试。
8. 可靠外部回执一到就保存素材/产物映射与分项状态；文件已入库、标签或权限待核验时，走继续核验或经授权补救，不能再次上传该文件。缺乏可靠关联的结果保持未知并人工核对。完成核验后关闭任务，不自动公开、不调用投放推送、不扩大橙子个人成果的可见范围。

C33/C34明确：云管家是正式标签唯一真源，橙子是缓存和受控操作入口。清单修改同步保存为草稿中的待提交选择；经人审提交并核对云端结果后，正式缓存按云端记录更新。云端直接修改时刷新缓存，不让两份正式标签竞争权威；未提交的本地选择保留为待重新核验意图，不自动反向覆盖云端。

本地未上传切片/草稿仍可按云字典选择标签并继续使用，不因标签真源在云端而强制上传。AI分析、工程结构和审核证据仍由橙子管理，不属于云标签字典。分类/标签选择改变要重验批准，历史批准快照不可回写；C35已确认橙子可发起云端标签创建；刷新时效、条件更新、创建回执/本人权限及恢复机制仍需验证，详见07第5/8节。

资料依据见[智尚接口能力与系统协同](04_智尚接口能力与系统协同.md)。当前只实测到公司认证成功和指定账号筛选成功空列表，真实分类、标签、个人权限、视频字段、上传可见范围均未验证；账号挂起不改变这些证据等级。

### 从橙子创建新标签的子流程

C35已确认：用户提交新标签 → 云管家创建 → 核实真实云端标签记录 → 同步橙子缓存 → 草稿/上传清单可选用。正式标签真源仍只有云管家。

工程建议：创建待处理、失败或结果未知时，只保存请求状态，不给临时本地标签赋予正式身份；必要时对账，防止不明结果重复创建。AI新词仍是建议，用户发起创建不等于同时批准上传媒体。该入口不自动获得管理员权限，也不扩大到其他账号；本轮不实际创建标签。

## 7. 推荐的工程分层与统一底座

核心技术方向按C87已确认；下表区分已定方向和配套工程基线。统一语义、契约和责任，不强行统一所有语言，也不把逻辑模块拆成六个微服务。

| 层 | 推荐职责 | 选择边界 |
| --- | --- | --- |
| 客户端界面 | Electron壳、React＋TS橙子前端，film替换原工作台 | 已确认；复用上游Studio编辑区，不复刻旧时间轴；版本/安全/性能待验 |
| 本地应用层 | Node＋TS编排个人工程/索引、清单、持久任务、文件与IPC | 配套SQLite及受管文件为工程基线，驱动/恢复待验；供应商URL不作主键 |
| 媒体工作进程 | 保留.NET Fission，受控媒体子进程隔离崩溃及资源预算 | .NET已确认；不为全Node重写计算，不默认引入Python；协议/工具版本待验 |
| 橙子可信服务 | Node＋TS服务承接第一方权限、组内原子去重、绑定、批准验证、供应商与积分 | 技术方向已确认；模块化单体为工程基线，非Edge主后端；媒体计算留本机 |
| 数据与基础设施 | Supabase Auth/Postgres为配套工程基线 | 不创建项目或改配置；身份迁移、区域、RLS、备份及网络待验证 |
| 边界适配 | OpenFilm原生格式、Fission工作协议、剪映格式、智尚字段分别适配 | 一份共享领域契约和兼容样例；禁止各模块自行另造ID、表名、状态 |

必要的共同机制：

- **任务中心**：持久任务、逐项状态、每次尝试、取消、恢复；批量100不等于并发100。CPU/GPU/内存/磁盘按实测预算调度。
- **边界验证**：不信任客户端路径、媒体文件、Agent命令或工作进程回报；检查文件访问范围、资源引用、契约版本与实际产物。
- **可信权限**：公司密钥和数据库高权限密钥仅在可信服务端；桌面内置Node并不等于可信服务端。暴露数据还需逐行/逐对象授权，不能只在页面隐藏。
- **一致性**：本地工作进程只汇报事实，由任务负责人提交状态；云端预占通过原子约束防竞争。跨本机、橙子云和智尚不虚构一个大事务，通过持久记录、幂等、对账和补偿恢复。
- **可追踪**：从一次用户操作到计划、修订、产物、批准、供应商请求串联关联ID；审计与运行日志分开，禁止记录密钥、令牌和带凭据URL。
- **依赖治理**：上游固定版本、补丁台账、兼容样例及升级演练；保留许可证。当前研究克隆不是完成集成，也不是GitHub fork。

物理目录与依赖白名单统一到[13技术架构与目录依赖基线](13_技术架构与目录依赖基线.md)，本文只保留职责图，不另列竞争目录。保留上游原生组织及必要编辑包，通过film-adapter受控接入；原生格式不直接成为橙子业务API。治理细项见[工程治理框架](01_工程治理与证伪框架.md)。

### 7.1 云端AI与本机媒体处理

本节是对当前讨论方向的架构建议，不是模型接入已完成或本轮外发素材的授权。采用云端模型时，推理发生在模型服务端；本机负责输入准备、接收结果和媒体执行，不能称为全程本地处理。仅在本机实际运行模型时，才是本地推理。具体供应商、可发送的数据类别与服务端留存/训练使用配置须核验，不能默认“请求结束就删除”。

| 能力 | 按任务发送的必要输入 | 模型结果与本机职责 |
| --- | --- | --- |
| ASR语音识别 | 需要转写的音频 | 返回带时间码文字；本机校验、展示、字幕编辑及候选区间关联 |
| JEV评分与选片辅助 | 录制/片段转写及任务上下文，输入依具体方案 | C61已确认评分业务，具体模型/维度待验证；分数绑定输入版本，不当人审或自动淘汰依据，不生成不存在的片段/时点 |
| LLM生成/归纳 | 所需文字稿、用户要求、受限素材/标签上下文；选定创作记录/修订与反馈 | 返回文案/编辑候选及C54纪要总结候选，人确认后正式沉淀；模型不批准团队共享 |
| TTS语音合成 | 普通配音的文案及授权音色参数 | 返回音频；登记实际音频版本、时长并保存为工程依赖，本机排布音轨/合成 |
| 视觉分析候选 | 仅在使用视觉模型时发送所需视频帧或片段 | 返回画面分析候选；不是默认把所有画面传给上述每个模型，无声产品素材不能硬套字幕评分 |

JEV一行依据已研究的[JevClip固定版本](https://raw.githubusercontent.com/cclank/jevclip/3d4b13f6ecbb7f56cf212c5040b4b4e19d83967a/README.md)：该路径消费已有字幕/文字稿，ASR另接，媒体裁切由本地代码/FFmpeg执行；不能据此承诺视觉高光识别或Windows兼容已经通过。

建议由橙子统一AI任务层对接各提供方，可信服务管理密钥、权限、用量和积分；素材加工、Fission和film复用这一层，不各自建立账号、计费或重试系统。原始媒体和工程仍以本机工作流为主，按任务最小化准备必要输入，不默认上传整库。凭据不打包到客户端，也不写入日志。

同一素材的分析按阶段输入版本/模型配置缓存，避免批量100条时重复转写同一素材；TTS实际音频确定后再用于时间线和组合判重。模型失败不等于素材无价值，不用随机重组或重发有副作用请求掩盖未知结果。云端AI调用并不取消本机预览、切片、渲染的资源预算和崩溃恢复。

### 7.2 内部成本与积分

**已确认C36/C39**：现阶段企业内部使用，橙子统一管理模型费用，积分归稳定的橙子账号；换机不重置、不按智尚绑定另算。客户端可展示缓存余额，但实际积分以账号账本为准，多设备操作不能各算一份余额；并发预占/结算是工程责任。对外收费、充值及套餐以后讨论。

工程建议区分两本账：供应商实际调用消耗/费用账，以及用户内部积分流水。二者关联任务但不强制等值；一次业务任务可能包含多次模型调用，失败也可能已产生供应商成本。不能把每次HTTP重试都机械转成一次用户扣分，也不能将未知消耗直接记为零。

C47/C73明确仅成功模型使用消费，失败或未成功取消不计、部分成功只计成功部分，已扣失败退回或释放预占。供应商实际成本独立，普通本地导出不收模型分；成功计费单元/费率、发放、预算数值和成功后取消/未知对账的工程协议仍需收敛，重复回执不重复扣退，旧额度不直接1:1映射。本轮不实际扣退，详见07第9.3节。

### 7.3 断网按依赖降级 不全面锁死本地工作

**已确认C40**：新组合先联网准入，已准入且依赖齐全的任务断网继续本地完成，联网后补登记。不因网络中断全面锁死本地工作，也不增加终态必须联网才能取得合格本地产物的门槛。

云素材检索/下载、标签同步/创建、在线认证或续验，以及C21的小组共享查重与预占，仍有在线依赖。以下列出已确认边界；会话时限、占用持久化及恢复机制仍是工程设计/验证项：

| 操作 | 断网行为与工程边界 |
| --- | --- |
| 已有本地工程、齐全依赖、当前可用授权下的编辑/保存/预览及导出 | 继续本地执行，不把上传、模型调用或云回执作为所有本地动作的附加前提 |
| 已完成在线查重与预占的Fission条目 | 若无需新模型结果且素材/音频等已就绪，继续执行和校验；分别保存本地交付事实与待同步的历史记录，联网后补登记 |
| Fission新批次、重组或用于补齐原批的二次编辑新内容尚未准入 | 可以本地准备、编辑和规划；新增共享查重/预占等待联网，未获准不能按已准入生成计数 |
| 云素材下载、云标签同步/创建、云模型、上传 | 等待网络恢复；本地已有音频/字幕/素材仍可按权限使用，保存清单不等于已上传 |
| 新设备首次登录或需在线重验 | 无法假装在线认证完成；已有会话的离线有效期与受限素材权限由工程形成规则 |

为实现C40，工程必须保证服务端不因心跳超时就直接释放可能仍在本机执行或已交付的组合，再分配给其他成员；需要持久占用、补登记和未知结果核对规则。不得把过期状态、已取消或已撤销授权的任务一概当作可继续；这些条件须一并验证。普通本地导出与云端历史/上传状态分开，离线缓存积分不等于允许脱离账号账本自行扣改余额。

### 7.4 创作经验 模板技能与共同观测

**已确认C49/C50：** 首版创作中心和超级混剪支持“保存为我的模板／技能”，人工确认后按用户归类沉淀，默认个人私有，持续迭代为公司资产。它是橙子的共同业务能力，不是film/Fission各自的私有知识库，也不是智尚素材标签库。

C54确定LLM纪要后人确认，工程闭环建议：确定工程/配方修订与必要操作事实 → LLM纪要/经验总结候选 → 人工核对确认 → 普通用户默认私有且公司管理员可治理的版本资产 → 当前权限下应用于新素材/任务 → 采纳/修改/失败反馈 → LLM归纳与人工确认新版。人工确认保存与技术可执行性、实际效果分开，不要求用户为每次操作填理由，不从点击推断真实意图。

工程层复用ProjectRevision、FissionRecipe/Plan、Job及其版本引用；新资产保存参数化定义和依赖，不维护第二条可变工程时间线。受控步骤可由人工或Agent执行，仍核验对象修订、素材权限和支持集合；复用不绕过组合准入、积分或上传确认，模板保存不算成片完成。

C52/C53已明确：其他普通用户默认不可见，公司管理员可查看管理本公司沉淀资产，员工离职后公司保留版本、来源和审计。该管理角色不直接开放所有原工程/媒体或智尚账号；离职保留不延续离职访问，不级联删除公司资产。C55要求团队共享另有明确人工确认，指定内容版本与目标团队，不由模型、管理员查看或离职自动触发。公司目录/备份、必要同步、角色/管理动作、共享撤回/更新和交接流程按D08/D24细化，不再讨论上述原则是否成立。知识分类在橙子域，正式素材标签仍以智尚为真源；LLM纪要不等于自动训练/微调或跨用户无界取材，不自动上传原工程/媒体。

**已确认C51：** 性能/错误观测横跨UI、IPC、工作进程、AI和云服务；标准日志及追踪关联任务/尝试/修订，审计记录关键确认和副作用。创作资产、运行遥测和审计各有存储/权限/保留责任，不能用可采样日志还原知识或积分账本。观测故障不锁死编辑；C40已准入任务保留可靠本地证据后仍可交付，未知云回执不冒充成功。

完整首版要求及待验证矩阵见[PRD FR-11与第10–12节](../06_橙子生产级重构PRD.md)，候选契约统一在07 §6.5/9.4；本轮没有部署知识服务、收集用户行为或改动现网。

### 7.5 IP撤回与公司操作记录

已确认C57/C58：对应账户不能再看到或请求已撤素材，公司保留业务操作数据，不删除。素材中心、工厂、编辑、混剪、草稿、交付及Agent共用有效访问规则；公司记录留存不把内容重新开放给被撤账户，也不自动开放所有管理员读取原工程。

工程提案：执行授权与四类人工确认分别记录；撤权按账户和资源范围传播到列表、检索、代理/缩略图、转写、历史引用及在途输出。保留工程结构和来源记录，受限内容仅显示不泄露内容的无权提示；恢复不复活旧授权。公司业务操作记录可靠落盘、离线补登并核验持久留存，不依赖可轮转诊断日志；公司副本不成为第二可变工程权威，不等于全量媒体同步。四类确认中的云上传指向云管家交付切片/审核通过的AI补充素材/成片，公司必要记录同步不等于媒体外发；模型输入按明确的数据外发范围/服务策略执行，Agent全权限不增授外发权。

已成功但仍由橙子管理的历史视频/剪映包，同样按当前来源权限或明确有效的独立授权判定预览、下载、重传；不能以本人归属、历史成功或保留文件绕过撤权。保留成功事实与公司记录，不声称可追回系统外副本。

C40仍适用于授权有效的已准入任务；无法在离线设备保证实时发现新撤权，也无法保证收回系统外明文文件。撤权传播时效、受限资源离线窗口、在途隔离及派生物独立授权边界按D09取得证据后评审，不把限制伪装成已经实现或默许继续使用。

| 安全与旧数据迁移 | 越权隔离、密钥边界、归属对账、浏览器本地库盘点、声音与历史恢复 | 待验证，见V35–V39 |

以上能力验证只能在后续明确授权的实验阶段执行；本轮没有新建服务、数据库表、测试工程或调用供应商接口。不能承诺“绝对稳定、安全”，应将其转为可测目标、发布门槛和恢复证据。

## 11 本轮业务边界对架构的约束

- C85：启动/重启必须第一方在线鉴权，运行中断网按C40；第三方智尚或模型不可达与橙子鉴权不可达分开。离线冷启动不凭缓存进工作区或自动执行，保留文件和记录；有效会话与有效素材许可分别核验。
- C81：工程和素材以个人为单位，首版不提供普通用户分享原工程/素材。公司管理员的知识治理权限与共享案例库收录权限分别建模；案例必须是已公开且有相应共享权的素材，并有管理员人工确认；仅管理员可读但未公开的素材不收录，不反向开放私人原工程，不改变同组判重。
- C82：派单/通知/回传由云管家承担，橙子只在接口有证据时镜像本人绑定可见数据，不另建流程引擎；不做应用内摄像，应用内录音保留。
- C83：重做、关联补充批并存；故障重试/已有交付重导出不混成新创作。原结果与历史保留，关联批也不能绕过去重。
- C80/C86：积分基准和1分起扣可版本化调整；执行前固定规则、幂等结算与原版本冲正。公司供应商成本独立，非Token换算不猜。
- C84/C87/C88：橙子壳体及其他业务页视觉延续，创作中心以film复用上游Studio编辑区并替换旧工作台，不要求复刻旧编辑区；12维护视觉基线，13维护技术依赖，不能形成两套导航、账号或资产浏览规则。
