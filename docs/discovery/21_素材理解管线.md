# 素材理解管线

文档集 U2（2026-11-13）。起点 `dev @ 3f66692`。职责：说明「把一条视频变成可检索的理解结果」这条链路的实测口径：本地视觉模型怎么调、抽帧参数怎么定、ffmpeg 有哪些已知坑、文字为什么必须走 OCR、以及 Jev 与云端备选的位置。

证据形态：本文件的时延与失败码全部来自本机实测；复跑入口是 `packages/openfilm/src/analyze-resolution-bench.mjs`。没有实测过的组合一律进末节待定。

## 2 本地视觉模型

### 2.1 端口与模型

- LM Studio 在本机监听 **1235**。写死 1234 会在「用户自己开过 LM Studio」的机器上连到别的实例或连不上。
- 模型 `qwen2.5-vl-7b-instruct`。7B 这一档是「能在本机跑起来」的取舍，不是质量结论。

### 2.2 输入格式

- 必须 `image_url` 指向 **base64 data-URI**。给 http URL 或本地路径都不行。
- webp 的 data-URI 前缀（`data:image/webp;base64,`）实测有 bug，模型侧解析失败。**只用 png/jpeg**。这条直接决定抽帧编码，见 §4。

## 3 时延与分层

### 3.1 实测时延

| 场景 | 数值 | 备注 |
| --- | --- | --- |
| 冷启（首次请求，含模型加载） | 26.8 s | 一次性成本，必须与单帧成本分开计 |
| 热态，小图 | 1.35 s | 稳态下限 |
| 1280 长边真实帧 | 20.3 s/帧 | 不可用于批量 |
| 768 长边 | 6.4 s/帧 | 中间档 |
| 512 长边 | 4.1 s/帧 | 当前默认 |

复跑：`node packages/openfilm/src/analyze-resolution-bench.mjs`。改分辨率或模型后必须重跑，不要沿用旧数字。

### 3.2 总量测算

已知素材量级 17.9 万条（智尚 `video/list` `total=178310`）：

- 12 帧/条 @512：`178310 × 12 × 4.1 s ≈ 2450 h`；
- 6 帧/条 @512：约 **1200 h**。

结论：默认 `--frames 6` 是容量约束下的取值，不是质量最优值。任何「全量跑一遍」的方案必须先说清帧数与分辨率，否则数字没有意义。

## 4 ffmpeg 已知坑（全部实测）

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| mjpeg 像素格式 | 直接 `-c:v mjpeg` 报错 `-22`（Invalid argument） | 显式 `-pix_fmt yuvj420p` |
| `-vsync` 参数 | 新版 ffmpeg 已移除，传了会失败 | 用 `-fps_mode vfr`（或 `cfr`） |
| `fps=1,select=gt(scene,…)` 组合 | 输出 **0 帧**，退出码却是 **0** | 不要串在 fps 之后；先 select 再 fps，或单独跑；**必须校验产出帧数**，退出码不可信 |

第 3 条是最危险的一条：静默产出 0 帧且成功退出，会让下游「没有画面」被当成「素材没内容」。抽帧步骤必须显式统计输出文件数并与预期比对。

## 5 文字与品牌：为什么必须 OCR

同一张封面：

- VLM 输出「李锦记」「丰阳茶」；
- 实际文字是「李陌茶」。

这类错误不是偶发噪声，而是 VLM 在中文短文本上的系统性替换（把不认识的字替换成常见品牌词）。因此规则定为：

1. **文字走 OCR**，不进 VLM 提示；
2. **品牌/产品名只信「元数据 + OCR」** 两个来源；
3. VLM 读出的任何文字只进 `hints`（供人参考的提示），不参与判定，也不落成结论字段。

这条规则同时解释了为什么 wiki 层的 `brand` 实体必须由 OCR 与元数据驱动，而不是模型自由生成（见 22 号文档的分类学）。

## 6 Jev 的位置

官方文档 `docs.typesafe.ai/images` 明确：

- `Jev 1.13 / 1.14` 接受图像输入，需要请求头 `TypeSafe-Danger-Zone-Images: true`；
- 提供 **Box** 原语，返回位置（不是只有一句话）；
- 标注 **Dreamer-ready**；
- 输出是**类型化判定 + 置信度**，不生成自然语言纪要。

推论（落地口径）：Jev 适合做「可判定的结构」（有没有人、有没有商品、画面区域），**不适合**直接产出中文摘要。纪要卡由我们自己的编译层生成，见 22 号文档；Jev 的置信度作为证据入 `wiki_source`，不替代人审。

## 7 云端备选

`deepseek-flash` 实测：可读图并读出图中字符（`A1`、`B2`），6.2 s/张，约 1.3k tokens/张。

用途限定：

- 只作为本地模型不可用时的**备选**，不是默认路径；
- 单张成本与 token 量已实测，但**未做批量与并发实测**；
- 涉及付费调用，需按 00/17 的授权口径执行，本文件不构成调用许可。

## 8 抽帧命令形状（含已知坑）

两种取帧方式，本文件只给形状与必须位上的参数；正式参数以分析脚本为准。

**A 场景切换取帧**（优先，命中率取决于素材节奏）：

```
ffmpeg -i IN.mp4 -vf "select='gt(scene,0.3)',scale=-2:512" \
       -fps_mode vfr -pix_fmt yuvj420p -q:v 3 OUT/%04d.jpg
```

**B 定点均匀取帧**（兜底，保证条数）：

```
ffmpeg -i IN.mp4 -vf "fps=1,scale=-2:512" -fps_mode vfr -pix_fmt yuvj420p OUT/%04d.jpg
```

两条都必须遵守 §4 的三条结论：`-pix_fmt yuvj420p` 必带（mjpeg 编码器）、`-fps_mode vfr` 代替已移除的 `-vsync`、**不要**把 `select=gt(scene,…)` 串在 `fps=` 之后。

**产出校验**（不能省）：统计 `OUT/*.jpg` 的个数，与预期比对。因为 ffmpeg 在 0 帧时退出码是 0，脚本必须自己判空，否则「没画面」会被误报成「素材没内容」。

## 9 一次理解调用的形状

| 环节 | 做法 | 依据 |
| --- | --- | --- |
| 输入 | 单帧 png/jpeg 编码为 base64 data-URI，塞进 `image_url` | §2.2 |
| 提示词 | **不含**「请读出图中的文字」，文字识别交给 OCR | §5 |
| 输出 | 结构化：场景/主体/构图等可判定字段；任何读到的文字放进 `hints` | §5 |
| 冷却 | 同进程连续调用，避免每帧重新加载模型（冷启 26.8 s ≫ 热态 1.35 s） | §3.1 |
| 计量 | 按「帧」记账：`条数 × 帧数 × 单帧时延`，冷启单独计一次 | §3.2 |

一个常被忽略的点：`hints` 是**给人看的**，不是给下游判定用的。任何从 `hints` 里再抽字段的逻辑都属于「把模型的猜测当事实」，与 §5 的规则冲突。

## 10 与下游的衔接

本管线的产物是「一条素材的证据集合」，落到 `wiki_source`（见 22 号文档 §2）：

- 证据层不可变，所以模型换版本重跑时按 `content_hash` 复用，而不是覆盖；
- 视觉描述、OCR 文本、元数据三者**分开存**，不在这一步合并——合并与冲突判定属于编译层的职责（`apps/api/src/wiki/compile.ts`）；
- 因此本管线**不做**「这条素材讲什么品牌」的结论，只提供证据。

## 11 错误分级

| 现象 | 归类 | 处置 |
| --- | --- | --- |
| 连接失败 / 端口不对 | 环境阻塞 | 检查 LM Studio 是否在 1235 监听；不重试到超时 |
| 冷启 26.8 s 超时 | 环境阻塞 | 预热一次再计时，别把冷启当失败 |
| `image_url` 解析失败 | 输入格式 | 检查是否 base64、是否 png/jpeg（webp 前缀有 bug） |
| 抽帧 0 张 | 输入/工具 | 校验帧数后终止该素材，**不**当成「无画面」 |
| 单帧时延远超基准 | 环境/负载 | 记录实际分辨率与并发，不要靠调参掩盖 |
