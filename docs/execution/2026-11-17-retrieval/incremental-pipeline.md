# 后续怎么跑：增量四步，不再全量重贯通

日期 2026-11-18 · 结论：**日常只跑增量；全量是"一次性、可中断、跑完就不再碰"的事**

## 一、现在是什么状态

| 位置 | 内容 | 说明 |
| - | - | - |
| 本机 Postgres（Docker） | 67 156 条，4096 全维 + 1024/512 投影 + HNSW 索引（1 080 MB） | **权威副本**，检索质量以此为基准（混合 88.5% / 同组 100%） |
| 云端 Supabase（免费额度） | `media_doc` 6 800 条**样本**，512 维列与 `media_search_512` 已就绪 | 轻量档：全量 67k 时约 323 MB；当前不再全量灌 |
| 代理/Docker | 目前都没在跑 | 机器是空的。云端推送需要开直连窗口（见第四节） |

全量重新贯通一次要：嵌入 67k × 4096（约 1.5 小时 GPU）+ 上传 67k 元数据（约 2 小时）+ 512 向量（约 1 小时）。
**这件事只该在"语料模板变了"或"换模型"时做一次，不是日常操作。**

## 二、日常一轮：四步，各自只做没做过的

```bash
node scripts/media-daily.mjs --limit 500          # 默认不推云端
node scripts/media-daily.mjs --limit 500 --cloud  # 连云端一起推
node scripts/media-daily.mjs --dry-run            # 只看会执行什么
node scripts/media-daily.mjs --only embed         # 只跑某一步
```

| 步骤 | 做什么 | 为什么不会重算 |
| - | - | - |
| `scan` | 供应商页 → 索引条目 | 按 `videoId` 合并，已有条目不动 |
| `embed` | 只嵌入 `text` 变了的行 | `--changed-only` 先比对库内 `md5(text)`；没变的行一次嵌入都不付 |
| `levels` | 回填 `one_level` / `two_level` | update 带 `is distinct from` 守卫，第二遍 0 次更新 |
| `push` | 只推云端缺的行 + 512 向量 | 云端 `ops.cloud_uploaded` 差集 + `--missing-only`；两段式（先建行、再补 512 列） |

## 三、资源纪律（"电脑吃得消"的具体做法）

- **并发固定 2**，不是 4：LM Studio 单卡排队，4 并发只是把 p99 抬过 20 s 超时线，重试变多、总时长没变；
- **单次上限 2 000 条，跑完就退出**：不常驻、不占内存；没跑完的下一轮继续（进度文件断点续跑）；
- **一次 500 条的实际开销**：8B 嵌入约 200 秒 GPU、上传约 1 MB 带宽、内存峰值 < 1 GB；
- **`push` 默认关闭**：它要求把 5432 走直连（本机代理只放 443），不该每天自动开窗口；
- 任何一步失败都不影响其它步；每一步都能单独重跑。

## 四、云端那条腿的约束（免费额度）

- 只放 **512 维**（MRL 投影）：67k 全量时 存 139 MB + 索引 161 MB ≈ 323 MB，免费额度装得下；
- 检索走 `media_search_512`（同样四路 RRF 融合），实测 **recall@20 84.0% / 同组 96.5%**；
- 4096 全维只在本地保留（2.06 GB），云端不放——放不下也不必要；
- 推送需要开直连窗口：`node scripts/supabase-route.mjs -- <命令>`（本机 mihomo 只隧道 443，5432 走 DIRECT）。
  如果 mihomo 没在跑，这条包装器会直接透传，不影响命令本身。

## 五、什么时候才需要"全量"

只有三种情况值得重跑全量：

1. **文档模板变了**（`materialDocText` 改了渲染顺序/字段）→ 全体 `text` 变化，必须重嵌；
2. **换嵌入模型或维度**（比如 4096 → 别的）→ 换 `embedding_ver` 新开一列，旧列作废；
3. **语料来源大改**（重新扫了供应商全量，条目大范围变化）。

判断依据不用猜：`--changed-only` 的第一次运行会打印 `changed / unchanged` 两个数——
`changed` 很少就说明是日常增量，`changed` ≈ 全量就说明该按"全量"对待（并挑一个空闲窗口跑）。

## 六、定时（可选）

想让它每天自动跑一轮增量，用 harness 的定时任务即可（不要用常驻进程）：

```
每天 03:00 → node scripts/media-daily.mjs --limit 2000
```

不推云端就保持默认；哪天要同步，手动加 `--cloud` 跑一次，或单独排一个更早的时间点。
