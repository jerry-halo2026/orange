## 3. 云管家是标签唯一真源

C33/C34已确认：云管家是正式标签唯一真源；橙子保存云字典/云资源标签的缓存，以及尚未向云端提交的修改，不是第二个标签主库。上传清单修改同步草稿是保留待提交选择，不代表本地修改立即成为已生效云标签。以下映射、刷新和提交机制仍是工程建议，不等于已验证真实字典或授权自动修改云端数据。

### 3.1 必须分开的三个概念

1. **分类**：视频分区下的一级/二级分类。
2. **供应商标签**：公共标签、个人标签及其层级、启用状态、适用分类和外部ID。
3. **橙子语义分析**：ASR文本与时间戳、人物/产品/动作/场景建议、选片分数、模型版本、置信度、人工修订和审核记录。

云端标签不是ASR全文、镜头分析或工程元数据的替代物。当前文档没有给出完整的ASR、嵌入向量、逐帧识别、切片审核证据或任意附件存取契约；不能假设上传视频会自动保存这些结果。文档内“附件”检索未发现对应说明，完整解析包仍应由橙子保存或另行确认供应商附件能力。

按C34，正式标签选项来自本人绑定范围内云管家的可用字典；建议用外部ID及作用域映射内部引用，内部tagId若保留只是稳定引用，不获得另建词典或自行改名/停用的权威。AI未知词仅作为待处理分析建议，不冒充正式云标签，也不自动创建公司公共标签、乱填近义词或静默删去必填项。C35已确认用户可从橙子发起新标签创建：由云管家创建成功并确认有效云端记录后，再同步到橙子的正式缓存。这是已确定的产品入口，不再列为待决；AI建议本身仍不自动授权创建。

### 3.2 标签不是全局同名即同一项

映射至少包含供应商实例/公司范围、公共或个人标签类别、个人标签所属账号、标签外部ID、父级与适用类型/分类。标签名称只用于显示和辅助匹配，不能充当稳定主键。改名保留ID；失效或停用不能在新上传时继续无提示使用。

云端标签接口包含 `isRequired` 与 `isRequiredVideo`，但具体适用与组合规则应通过真实分类核验。日期字段要保留原值与来源；不能仅凭标签未过期就宣布已取得完整商用权。

**公共标签不等于公开素材，个人标签也不等于仅本人可见。** 标签类别与素材可见范围是两个权限维度。

### 3.3 一致性不等于即时写云端

工程建议：上传清单中的人工选择形成待提交tagRevision并同步草稿；正式显示依据最近一次可信云端回读，注明观测时间/同步状态。人审批准锁定选项、云字典映射和目标内容，提交后回读核验云端实际记录，再更新正式缓存。尚未上传、待提交、失败和待重新核验应可区分，本地保存成功不能冒充云端已生效。

云端直接改标签后，橙子的正式缓存应按云端记录刷新，而不是让用户选择两套正式标签谁为准。若有未提交的本地修改，建议保留该修改并标记基线已变、待重新核验；它仍是变更意图，不能自动覆盖云端事实。具体刷新频率、离线时效和重提交交互待D21决定；API是否支持条件更新仍未验证，云端唯一真源不等于已经实现无并发覆盖。

本地尚未上传的切片/草稿可按云字典保存拟用标签，并继续本地检索/创作；这些是准备态选择，不虚构已有云资源标签，也不为满足一致性而强制上传。后续修改已存在云资源仍须本人有效权限和明确操作范围，不自动影响其他作者、全部同源内容或历史批准快照。无法表达全部批准标签或无法核验时保留差异，不偷偷删标签或谎称成功。

### 3.4 接口限额不是一个统一数字

- 导入：一次最多50个视频，每个视频的标签字段注明最多10个二级标签。
- 批量追加公共标签：同一二级分类，一次最多50个视频、10个标签。
- 单视频编辑：提供覆盖或增删标签的方式，文档规定操作后该类型标签总数不超过100。
- 公共标签查询：pageSize范围1–100；创建标签组/子标签另有每次10项限制。

不能因为编辑接口允许100个标签，就在首次导入时发送100个。首版审核清单应按实际将调用的端点验证必填、范围与数量；无法表达全部已批准标签时应阻止提交并解释，不偷偷删减。也不能把所有选中视频强制套用同一组标签。

依据：文档4.5、8.2、8.4、8.9、8.10、8.15、11节；视频信息编辑（供应商受控文档，公开仓不包含内部链接）。

### 3.5 橙子发起云端标签创建

**已确认C35**：用户在橙子发起创建，实际创建由云管家完成；云端成功后再同步到橙子，云管家唯一真源不变。已读接口文档列有标签组/子标签创建能力及相应限制，不再将“能否提供创建入口”重复当作待确认产品问题。文档能力不代表当前绑定账号已获全部标签类型的写权限。

工程建议流程：

1. 记录用户明确提交的名称、父级/层级、作用域及本人绑定，校验云字典约束和实际权限；不能自动切换管理员身份或扩大范围。
2. 调用对应云端创建接口。橙子可以保存请求、进度和失败原因，但在云端成功前不把临时记录当作正式标签。
3. 根据创建回执及必要的字典回读，核实真实外部标签ID、父级、作用域和可用状态，再刷新缓存，供草稿/上传清单选用。HTTP成功或本地请求已保存不等于标签创建成功。
4. 响应丢失或结果不明时先对账，不盲目重发；同名记录必须按类型、父级、实例/公司及个人账号范围核对，不能任选一项绑定。具体幂等/唯一性保证须按接口行为验证。
5. 云端创建成功不自动上传素材或修改所有草稿；相关内容仍按选定标签与既定人审规则确认。创建失败不影响其他有效标签，依赖该标签的条目保持待处理，不偷偷换近义标签。

## 4. 账号归属与可见性是首版联调重点

### 4.1 本人归属不等于仅本人可见

导入文档要求 `account_key`，但视频对象没有单独列出作者账号字段。需要验证该身份是否决定最终作者/归属，不能仅因为请求带了本人账号就宣布归属正确。

导入的 `videoRight` 明列0公开、1团队、2小组、3公共资源。单视频编辑另外列出4指定范围，以及指定账号/小组/团队字段。**导入是否也支持4，文档不能证明。** “公开”在该私有化产品中究竟是公司内范围还是其他边界，也需供应商明确，不能擅自解释为互联网公开或仅本人。

已确认的是：上传本人绑定账号、不自动公开；橙子工程与成品个人可见。不能把这两条扩大解释成已确认“所有云端上传必须仅本人可见”，也不能反过来默认为小组共享。若选用团队/小组可见，需要用户明确批准该范围。

不采用先扩大可见范围入库、再事后修改的默认流程。两次调用之间存在已被他人看到或取走的窗口，后续修改不是可靠撤回。若用户批准的范围无法在导入时保证，应暂停云上传，保留本地结果与其他导出能力，或等待供应商提供受控入口。

### 4.2 公司凭据不能进入C端客户端

建议由服务端供应商适配器持有公司密钥和公司token，先核验橙子身份、本人绑定及本次操作权限，再按该绑定发起调用。客户端、OpenFilm、Fission、Agent均不直接取得企业密钥，也不允许自由指定其他员工的 `account_key`。

文档所列公司token获取流程不是云管家个人密码登录/OAuth绑定流程。供应商账号列表能发现账号，不等于证明其属于当前橙子用户；本人绑定证明、换绑和停用恢复仍属于待设计事项。姓名、工号、登录名和角色均不可代替橙子的稳定个人ID。

公开共享、标签字典维护、账号组织管理、对外推送各是独立能力。服务端不得因为持有一把公司凭据就把所有能力暴露为通用代理。撤权/停用时禁止自动回退到管理员账号重试。

依据：导入接口（供应商受控文档，公开仓不包含内部链接）、视频编辑接口（供应商受控文档，公开仓不包含内部链接）。

## 5. 一次确认上传不等于一个不可分辨的大请求

### 5.1 先解决本地文件如何被供应商取得

导入通过 `videoJSON` 字符串提交视频对象和URL，由智尚拉取文件；不是把Windows本地路径直接交给API，也没有在该接口中列出桌面直传分片协议。

建议：冻结批准文件 → 受控临时中转 → 生成仅供本次导入使用的可访问链接 → 智尚拉取 → 查询入库结果 → 核对 → 按保留策略清理中转。必须核验签名链接、有效期、断点/超时、URL重定向和供应商实际拉取方式。不要为了方便而永久开放存储桶；链接、token和完整私有路径不进入日志。

### 5.2 将业务批次、供应商请求和单条结果分开

用户可在一张清单上核对、逐条改标签、勾选多条、一次确认。后台应冻结具体选中集合，而不是执行时重新查询整个动态列表。

一批100条至少要按导入上限拆成两个不超过50条的请求；这是上限约束，不是推荐50条并发。可再根据目标绑定、可见范围、失败隔离和接口规则拆分。每个视频保留自己的标签与归属，不因拆批改变确认内容。

文档写同一导入请求全部成功或失败，却同时给出了 `success:true` 且 `errorList` 非空的示例；异步结果又按视频逐条返回。需要区分请求校验、受理、后台下载和最终完成的原子性。现阶段不能假设整批业务拥有数据库式事务保证。

### 5.3 必须有单条对账状态

- 提交前记录批准对象、文件版本/哈希、标签快照、目标绑定版本和批准范围。
- 区分响应顶层的追踪 `requestId` 与导入 `data.requestId` 的任务引用，不用同一个含糊字段覆盖。
- `/openapi/video/import/query` 文档状态为0待处理、3文件下载中、10成功、20失败；它不是视频转码 `state` 的枚举。
- 返回“导入成功”后仍需验证云端视频ID、可用性、实际归属、标签和批准可见范围；当前列表响应是否能完整回读这些信息仍待实测。
- HTTP成功或 `success:true` 不能绕过 `errorList` 检查；错误项索引的基数、逐条回执与原条目的可靠映射须确认，不能按重复文件名猜对应关系。
- 响应丢失时标记结果未知并优先对账；`thirdId` 被文档描述为第三方平台ID，并没有承诺它是幂等键。不得把再发一遍当安全重试。
- 文件已入库而标签/权限核验未完成时记录部分完成，不盲目重传已存在文件。
- 依据核实后的回执确定受影响条目；请求级失败可能影响同一请求全部条目，未知结果保持未知，不改写其他已确认成功项，也不盲目整批重传。导出视频成功、草稿成功、云端入库成功分别计数，不能互相冒充。

文档中推送成功回调属于第9节的渠道推送，不是已证明存在的导入完成回调。首版导入需要以查询接口为依据设计有上限的轮询和人工处理超时/未知结果；退避与频率待供应商配额确认。

依据：导入（供应商受控文档，公开仓不包含内部链接）、导入结果查询（供应商受控文档，公开仓不包含内部链接）。

## 6. 素材中心、加工、Fission、OpenFilm的关系

建议保持已经讨论的业务边界，并增加供应商契约隔离：

- **智尚适配层**：负责按本人绑定查询、映射字典、取得授权文件、提交导入及对账；不拥有橙子工程编辑权。
- **统一素材中心**：管理一个逻辑素材及其来源、文件表示/版本、授权、解析修订、人工审核、标签映射和本地/云端位置。云端多一个位置，不自动复制成另一个毫无血缘的素材。
- **素材加工**：从有权使用的原片产生ASR、候选片段和标签建议；经人工审核成为可用本地素材。上传是独立动作，不是本地可用的前提。
- **Fission**：使用可用素材快照和已排序的场景组产生冻结实际剪辑方案；源目录“1开场、2产品、3讲解”属于叙事顺序，不由智尚分类或标签顺序替代。
- **OpenFilm**：接收实际剪辑方案建立可编辑工程。进入人工/Agent编辑后，以工程修订为编辑权威，冻结Fission方案继续作为不可改写来源。
- **导出与上传**：Fission或OpenFilm的结果可直接导出视频、导出真正的剪映草稿；最终视频还可进入同一个审核上传清单。上传清单同时支持素材切片和最终视频，而非默认上传完整工程包。

可以形成“授权来源 → 素材中心 → 加工人审 → Fission/编辑 → 产物 → 确认上传 → 云端映射”的闭环；也允许不上传的本地闭环。三种交付不是三套重复身份、标签或资产表。

成片关联接口中的部分轨道字段只能作为供应商关系证据。其时间单位、完整性、音频/字幕/效果覆盖以及写回途径都不明确；不能拿它直接承诺OpenFilm工程或剪映草稿可无损重建。文档也没有证明支持生成或上传剪映工程包，剪映适配仍由橙子的专门适配层负责。

- `lastModifyTime` 文档仅称时间戳，秒/毫秒未明确；日期字符串的时区也未明确。保存原值，不凭数量级/机器时区静默猜测。
- 云端ID、原片SHA256和成片组合指纹是不同标识。不能拿videoId替代文件哈希，也不能拿导出后MP4哈希替代渲染前的组合判重。
- 供应商视频列表示例用 `id`，说明文字用 `videoId`；`viewCount` 与说明中的 `videCount` 也不一致。适配器必须经真实样本明确字段来源，不能无条件宽松兼容掩盖数据问题。
- 缓存键、同步游标和操作记录要包含调用绑定及版本/权限上下文，避免切换账号后读到另一个账号的素材或沿用过期授权。

## 8. 同步、并发与可追溯性

**不能在每次预览、每个混剪候选组合上重新查询整套云端目录。** 建议先取得有权限的素材/字典快照，按需下载并校验，在批次内引用固定版本。小组组合查重由橙子的指纹和原子预占服务负责，不依赖对智尚进行笛卡尔积式请求。

视频检索提供最后修改时间、更新日期与ES更新日期等筛选，可作为增量同步候选，但不等于稳定CDC：同时间多条记录、分页漂移、标签变化、回收/删除、权限撤销和组织变动仍要处理。建议重叠时间窗口、按ID/版本去重、周期性核对；无法取得时区/边界/删除规则前，不承诺无遗漏实时同步。

本轮第13节确认错误码20000参数错误、20001超时、20002频率过高、20013令牌过期、20014令牌错误、20015签名错误、20020账号不存在、20022账号无权限。适配器应区分可重试故障、身份/权限错误及结果未知，不能一律重试。当前核读未取得可据以承诺的QPS、日配额或上传并发上限。并发和退避应可配置，以公司连接及账号公平调度；10/50/100条业务批次不是10/50/100路并发。

认证文档要求秒级timestamp、16位nonce、排序与URL编码后的签名；公司token标称24小时。应封装在唯一适配器内并建立契约用例，特别覆盖JSON字符串、空值和多ID字段。MD5在这里是供应商的兼容协议，不是橙子存储密码或媒体校验的算法选择。

审计事件建议记录橙子操作者、绑定引用/版本、对象版本、批准记录、请求/任务关联、操作类别、结果码、耗时、重试次数和状态变化。不得记录密钥、token、完整签名源串、带凭据的下载URL、用户密码或全量供应商响应。下载原片请求会影响供应商下载统计，统计副作用也要纳入用户动作与重试设计。

## 11. 下一步只读核验清单

安全调用通道已验证；本轮按Ethan决定停止扩展查询。后续准确定位指定账号并满足授权范围后，再进行以下核验，不自动扩大为公司全量抓取：

1. 仅验证公司认证及指定登录账号唯一、启用匹配；不选择其他员工或管理员替代。
2. 读取素材/成片分类和适用标签、个人标签及状态字典，记录结构、必填/停用特征和计数；避免保存真实人员信息。
3. 素材与成片分别取一小页，只保留脱敏结构及字段类型，核对权限上下文、ID、时间和可见性字段。
4. 根据已返回分类做少量定向标签查询，验证关联与必填；不创建任何标签或分类。
5. 不调用原片地址接口，因为它增加下载次数；不下载/预览实际媒体、不上传、不编辑、不改状态、不推送、不创建账号或绑定。
6. 形成脱敏契约样本，区分“未返回”“字段为null”“无权限”“接口不支持”，不得当成同一种空结果。

之后如要验证真实上传、标签回写、可见范围和幂等恢复，须另行批准受控测试素材和清理方案；本轮只读授权不包含这些动作。

## 12. 对当前架构方向的影响

这些接口事实支持继续采用“橙子业务层 + 统一契约 + OpenFilm编辑基座 + Fission执行核心 + 素材加工 + 智尚适配器”的方向，但不构成“必须全部改Node”的证据。它们主要要求服务端权限隔离、稳定任务状态、字段映射及异步恢复，与保留.NET混剪核心并不冲突。

本轮收敛的是接口能力和风险，不改变已确认的Windows首版、720p/1080p、小组测试、个人工程归属、组内历史去重、人审后入库和三条交付能力。正式PRD应把这些接口验证列为验收前置条件，而不是承诺已经实现或绝对不会出错。

## 13 云协作复用的证据边界

**已确认C82：** 派单、通知、回传优先复用云管家既有内容，按本人绑定同步；橙子不另建跨人员协作平台，不做应用内摄像。此前核读已经证明账号、素材、分类/标签、关系及导入等文档能力；当前04的证据没有建立录制任务目录、通知事件、任务接收/指派、回传附件与工作流状态对应的开放端点。不能由“对应同一账号”推导上述接口已提供，也不能把视频作者或业务状态字段当作任务参与者/完成状态。
