## 1 已经对齐的整体方案

### 产品边界

- 这是橙子的生产级升级，不是另造剪映，也不是把旧橙子业务删掉只留下film编辑器。
- 首版 Windows、企业内部小组测试；独立橙子账号，另绑定本人云管家。未来对外使用的方向保留，对外收费后置。
- 当前典型负载是 3–5 秒素材、30–45 秒或 45–60 秒成片、10/50/100 条批次；不是强制时长、批量上限或同时执行数量。
- 默认 1080×1920、30fps、9:16，正式支持 720p/1080p。目标档位 i5/16GB/1660Ti+，先在 i7/4060/32GB 本机验证；其余支持范围及性能尚未验收。
- 云管家是正式标签唯一真源；橙子可发起新标签创建，云端成功后再同步。橙子保存缓存和待提交选择，不建立第二套正式标签。
- 费用由橙子统一管理，用户暂用内部积分；不在此阶段建设充值、支付或外部价格套餐。

### 业务闭环和模块责任

| 环节 | 负责的事情 | 与下一环节的关系 |
| --- | --- | --- |
| 素材加工 | 原片分析、候选区间、摘要和标签建议、本机切片及人工确认；具体 ASR/JEV/视觉实现尚未全部选型，见第 2 节 | 产生有来源血缘的可用素材版本，不由 AI 自动批准上传 |
| 素材中心 | 一个目录管理本地与云端素材、文件版本/位置、权限、正式标签缓存及个人使用记录 | 可用本地素材直接供 Fission/film 使用，不要求先上传；云端多一个位置不另造无血缘资源 |
| Fission | 按有序场景组和配方批量规划，冻结实际选材、区间、字幕和音轨，组内共享历史去重 | 可直接交付，也可把尚未渲染的方案交给 film；不必先生成 MP4 |
| film | 人工与 Agent 编辑、预览、保存工程修订 | 编辑后的修订成为当前编辑依据，不反向改写原始 Fission 方案 |
| 草稿箱 | 保存可继续编辑的工程、素材依赖、字幕、配音、标签和来源 | 后续继续编辑，或对选中修订批量导出、核对后上传；不是仅存 MP4 的待上传列表 |
| 交付与云上传 | 输出视频、输出真实可编辑剪映草稿；切片/成片经清单确认后上传本人云管家 | 三种后续处理共享同一内容来源；上传的是媒体文件，不是整个橙子或剪映工程 |

本地链路：取得有权使用的素材 → 加工及人审（需要加工时）→ 素材中心 → Fission / film → 保存草稿箱或交付。

云端链路：切片或最终视频 → 核对内容与标签 → 勾选并确认 → 受控上传 → 核对归属、标签和可见范围 → 保存云端映射 → 在获授权范围内再次使用。

**三种处理方式不是三套业务系统。** 同一工程修订可以先导出视频，稍后再导出剪映草稿或确认上传；C44已定生成后按需选择，关闭选择窗后可重开或单独选择出口，不默认预选一组必需项。保存草稿、成功输出视频、成功生成剪映草稿、成功入库必须分别显示，不能相互冒充。

同一工程来源也不保证转换后的实际内容相同。若剪映适配丢掉字幕、音轨或效果，须先报告差异，不能与未降级的视频静默拼成同一修订完成；若丢掉的恰好是两条方案唯一差异，也不能沿用原指纹算作两条不同内容。是否另建有效修订并重新判重，仍按 D05/D16/D20 收敛。

同组共享组合去重，但个人工程与成果不因此互相可见。重复先自动重组，补不齐集中引导二次编辑；重复、待编辑和仅保存工程不计视频完成数。允许保留成功结果主动结束，目标 100、成功 80 仍显示 80/100。

### AI 是公共能力 不是四套独立系统

以下为职责分工建议，不表示候选模型或算法已获首版选型批准。

- ASR：音频 → 带时间码文字，供字幕、检索和候选选片。
- JEV 类判断：已研究的 JevClip 路径消费文字片段，返回判断；不把它当成已验证的画面高光检测器。无声产品镜头需要视觉分析或人工判断。
- LLM：文案、归纳、标签及编辑建议；不直接写正式标签、审核决定或任意业务状态。
- TTS：文案及授权音色参数 → 实际音频；以实际音频版本和时长进入时间线、草稿依赖和组合判重。
- 本机：准备必要输入、校验模型结果、裁切、排布、预览、合成、导出与保存。

云端模型推理意味着必要文字、音频或画面已发送给模型服务商，不等于全程本地。各板块复用同一能力调用、权限、缓存、任务和计量规则，不默认把整库或每条视频的全部信息发给所有模型。详细依据和边界见[06 第 7 节](06_整体架构与业务闭环.md)。

## 3 真正需要补强的缺口

### 3.1 保留创作自由 不增加强制创作单

**C42已确认，不再作为待决缺口。** 前版建议统一创作单、单商品/规格或必备镜头约束；Ethan指出这会限制创作空间，首版不把它们作为默认准入门槛。旧代码中存在商品/风格等字段，只说明可供用户选择，不是新产品必须锁定同一商品或禁止混用的依据。

工程只贯彻用户自己选择的素材、配方、场景组顺序及明确提出的要求；可选备注不能变成必填创作说明。C43的画面/字幕/音频匹配、文件有效性、C19组序、C20去重和账号隔离仍保留。不能靠系统自行增设创作限制来代替内容预览与人工决定。

### 3.2 文件可播放不等于内容合格

**分类：已有考虑，但验收口径不完整。** 技术验收、符合创作要求、人工认可，应分别记录。

- 技术层：文件完整、实际规格正确、音画同步、时间范围合法、依赖存在。
- 内容匹配层：按用户选择和明确要求核对画面、字幕、音频，字幕不过界，关键口播不被音乐遮盖；不默认禁止跨商品或强制必备镜头。C43允许口播不铺满，以BGM配合无口播段，不把留白一律判不合格。
- 人工层：节奏、表达和素材含义是否合适；模型评分不能等同人审通过。上传前已有内容/标签确认，不能拿它替代本地直接导出的质量规则。

TTS 实际时长虽已纳入方案，但还缺超长/过短处理：若某次任务明确要求 45 秒，而配音实际 46 秒，建议先提示待修，不静默截尾、提速或改稿。30–60 秒仍是典型值，不擅自升级成所有任务硬上限。换配音或改词后，相关字幕对齐和检查要重新完成。

建立橙子真实样例集：商品专名、数字/价格、口音、无声产品镜头、原声/配音/BGM 同时存在等。ASR 错词率之外还应观察关键事实；JEV 在带货内容中是否误删“广告段”；LLM 是否编造卖点；新模型/提示词是否让已确认结果发生漂移。自动检查不能承诺识别所有语义错误。

责任：工程提出自动检查和固定样例的人工质量验收，不把“逐条审批或抽检”设置为本地导出的默认业务门槛。只有未来确需新增强制复核/阻断政策时，再明确其业务影响并请求决定；四类已定人工最终确认不变。依据：06 §3/§5/§7.1，07 §6/§11。

### 3.3 AI 调用边界和费用治理尚未闭合

**分类：已讨论但未收敛，不是重新讨论由谁付费。**

建议补齐：哪些输入允许外发、允许的提供方及留存条件；按任务最小化输入；缓存键同时考虑内容/模型/配置和授权范围；模型不可用时明确排队、失败或采用经批准的替代方案，不静默换模型改掉已审核结果。

字幕、云标签、文档和素材中的文字是待处理数据，不是给 Agent 的权限指令。模型输出只能经过白名单业务命令和当前操作者权限校验；不能借内容里的指令访问任意文件、执行命令、创建标签或批准上传。

C73只对成功模型使用消费，失败/未成功取消不计，部分只计成功部分；普通本地操作不收模型积分。公司成本、供应商限额和用户积分是三类控制，未知不当零成本或成功；C74开发暂无固定预算但要控制区间，不允许无界重试。C80/C86的Token基准、起扣和可调已定，剩余计量、发放及预算数值待决定，预估/预占/幂等结算与告警由工程提案。

对话中曾出现的凭据应由持有人轮换后再用于正式测试，之后通过安全配置交付；本轮不执行轮换，不重新展示或保存秘密。责任：工程负责调用、密钥及对账机制，Ethan 定内部计分和预算政策；提供方条件按官方文档核实。依据：06 §7.1–7.2，07 §9.3。

### 3.4 中断 部分成功和完成数量还缺统一状态表

**分类：已讨论但未收敛。** 本地文件、橙子记录和第三方任务不可能靠一个“成功”布尔值覆盖。

| 事实 | 建议展示及恢复方向 |
| --- | --- |
| 文件落盘后应用崩溃 | 启动时核对来源修订和文件，恢复记录；不默认整批重渲 |
| 云端受理但响应丢失 | 结果未知，先对账；不能盲目重传第二份 |
| 文件已入库，标签/权限尚待核验 | 保存可靠云端映射，继续核验或按批准范围补救；不重复上传文件 |
| 工程已保存，但未导出 | 草稿保存完成，不计视频完成 |
| 视频成功而另一个出口失败 | 分项保留事实；整体完成按最终批准的任务要求计算 |
| 用户主动结束，仍有任务在途 | 区分停止新调度、请求取消和实际结束；成功结果保留 |

C21/C40已确认：新组合先联网查重和预占，已准入且依赖齐全的任务断网继续本地执行、校验和交付，联网后补登记。不以缺少终态云回执扣留合格本地产物。云素材下载/标签同步也依赖网络，不是只有上传和云模型受影响。历史组合占用、本地交付与云端成功分别记录，未知执行不能因超时自动释放。产品边界已定，占用保留/幂等对账和故障恢复由工程设计验证，见06第7.3节。

责任：工程补“中断点 → 持久事实 → 显示 → 允许动作”表；离线续跑边界已由C40确认；C44已定交付可后选、重开或单独操作，工程需分别记进度；C64已定主动结束直接停止在途，取消/完成竞态与迟到回执由工程验证，工程负责离线持久化与补登记机制。依据：06 §4/§6，07 §7–§8，D16/D17/D20。

### 3.5 草稿保存之后 必须真的能恢复

**分类：C32 已确认保存目标，文件生命周期规则尚未收敛。**

把原件、工程固定依赖、可重建代理、临时中转和日志分开管理。两个工程引用同一音频或原片，删一个工程、清缓存或更新程序不能破坏另一个；AI 生成的配音也不能仅因“可再次调用”就当作可准确重建的缓存。

建议记录依赖清单、版本和校验值，并保护仍被引用的文件。导出前评估原件、代理、临时文件和成片所需磁盘；磁盘不足先停止可重算任务，不擅自清除用户成果。文件移盘后按版本/校验值重新定位，不按同名直接替换。

备份要包含工程记录和有权保存的必要依赖，验证在干净环境恢复；数据库备份不等于视频/工程依赖备份。受限素材不能因备份而获得更大权限。C38明确换机为新设备，本地视频资产仍在原设备，云资产仍在云端；不因同账号登录自动搬迁或上传本地资产，不将全量跨设备云同步捆绑成首版前提。

责任：工程按C38提出当前设备的文件分类、引用保护和恢复方案；不再要求Ethan重复决定是否自动随账号搬家。显式备份/迁移、非业务缓存清理及恢复目标另行定范围；C58公司业务记录保留不删除，不把可容忍丢记录当作既定条件。依据：C32、D08/D09，06 §5，07 §6.4。

### 3.6 撤权和素材事后纠错要沿依赖传播

**分类：已提及权限和血缘，但事后影响处理不完整。**

账号退出、换绑或成员撤权时，旧后台任务不能借新账号继续执行，迟到回执不能转投新绑定。橙子内个人可见、同组去重和管理员管理预算是不同权限；不推导为管理员天然可以浏览所有个人工程。C57已明确受限素材撤回后对应账户不可见/不可再请求，不能用已下载或历史工程绕过；离线传播/有效窗口需评审验证，外部已取得的文件不能承诺追回。

若某个已用切片被发现错标或包含错误事实，应能列出受影响草稿、待上传任务和已交付成片。建议标记旧版本不宜再用于新创作，不静默替换工程，不抹掉历史去重，也不自动删除云端成品。普通云标签字典变化与内容错误/权利撤回需要区分，不能每次标签刷新都使全部历史工程失效。

责任：工程按C57/C58实现对应账户访问限制和公司记录保留，验证缓存/历史引用/在途结果隔离及恢复不复权；撤权传播时效和离线窗口先给证据后评审，不再询问是否允许已撤账户继续请求或可见。素材纠错复核由工程设计；C70派生物沿用相同授权原则，无默认永久独立许可。系统外已导出明文无法保证收回，不能拿登录控制代替该限制。依据：D09/D10，PRD §2.3、V32–V34。

责任：工程制定本机威胁模型、进程/桥接权限及负向测试，无需 Ethan 选择底层技术参数。依据：01 契约规范、06 §7 已有原则；本节补操作级约束。
