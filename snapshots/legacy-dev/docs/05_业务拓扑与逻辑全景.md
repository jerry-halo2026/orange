## 1. 一句话定位

**公司内部短视频产能流水线**:39 名员工从公司授权的带货原片中检索、领取、逐字节校验、剪辑、导出成片;中台(central)管授权解析与审计,云视频管家存原片,统一账号中心管身份,Agent 只做"可校验的编排建议"不替人做决定。

## 4. 核心业务域深讲

### 域 1 · 素材授权与解析(中台)

**目的**:把"一段原片"变成"可检索、可授权、可追责的结构化素材"。

- 数据格式 `orange.unit.v1`(unit_schema.py):原片身份(`media{durationMs,bytes,sha256,version,identityVerified===true}`)+ 拆解段落 `segments[1..500]`(时间必须落在 durationMs 内;`audioMode∈{original,mute}` 允许重叠段落=同一画面的原声/静音两个候选;`reviewStatus∈{pending,reviewed,approved}`)。旧格式 `orange.segment.v1`(单段)兼容读取。
- **信任根**是 `register_parsed.py` CLI:校验 schema → mkstemp+fsync+`os.link` 原子 no-replace 写入 → 拒 symlink → 拒绝同编号不同内容静默覆盖(要求显式版本迁移)。未知 schema 一律拒绝(fail-closed)。
- 媒体变体协议:下载字节与登记 sha256 不符时,只有 `cloud-id+source-sha256+full-timeline-ssim-v1` 方法全项通过(含 ±100ms 时长)才允许替换 media 身份——这是"云管家重传了文件但内容相同"的唯一合法通道。
- 搜索(service.py:109):解析索引命中优先展示,未命中才回退云管家文件名;**返回前必过员工绑定与云管家权限**。已知限制:非跨索引联合排序(03 文档自报)。

**不变量**:视频编号必须同时与解析登记和实际文件校验一致;缺 MD5 拒绝导入;`rawBytes=0` 表示未知而非零字节。

### 域 2 · 审核发布生命周期(不可变快照)

```
draft ──review(记听审证据 evidence)──> published(不可变快照,定受众)
  ↑ import(manifest 存 canonical JSON;媒体签名摘要另存 media 表用于"同 mediaId 换版本"拦截;
    发布时计算 publication.sha256;领取侧 local.py:54,174 读取时复验——核查修正:catalog 自身读取不复验)
published ──withdraw──> withdrawn(只禁新领取,不删个人历史资料)
```

- `publish` 用 `BEGIN IMMEDIATE` 防并发重复发布(catalog.py:147);快照含 `upstreamReview`(上游旧复核记录保留但不自动信任)。
- **撤回语义是"授权收缩"而非销毁**:已领取的个人资料保留(历史既得),新领取禁止,新目录领取同媒体旧任务可重新授权。
- 个人备注与选用**钉死在领取时的目录版本**,新版发布不覆盖(local.py 选取逻辑)。
- demo.py 即此流程的合成演练:2 个合成片 → import → review(注明"仅验证流程,不代表真实素材通过人工听审")→ publish 给 ['employee'] → 再造一个 revision 2 待审 + examples/pending-unit.json(revision 3)供审核界面导入演示。

**意图**:员工只能用"人审过"的段落;版权追责有据;版本演进不破坏个人劳动成果。

### 域 3 · 领取下载与校验管线(本项目的心脏)

```
claim ──> downloading(.partial) ──> verifying ──> available
  │          │断点: 核对 206/起点/总长/ETag;200 则从头重写    │
  │          │ETag 变 → 失败,重试时整段重下                    │
  │          └──> failed(保留明确原因;错误不记录授权 URL)      │
  └──> paused(重启后显示已暂停,用户显式继续;单机并发=1)
```

校验链(local.py / cloud_bundle.py):**长度核对 → 原片 MD5 → 完整解码 → 实际时长核对(±150ms)→ 原子改名(os.replace)**。磁盘不足、链接失效、网络中断、哈希/解码/时长失败,任何一环不过都进不了可用态。

去重:同媒体版本直接复用;同内容跨媒体版本复用已验证文件(SHA256 命名)。取消的任务重新领取可恢复。

**意图与规模**:03 文档"196/199 全批次带溯源码版本验证"就是这条管线在 199 个原片上的批量执行,3 个未过(2 帧时间偏差+1 时长不一致)卡住发布——**校验器是商业契约,不是技术装饰**。

### 域 4 · 个人库与选用

- `selections`:选用+个人备注(钉在原目录版本);`exports/`:段落 MP4 + 配套 JSON(含原句、标签、版本与原片坐标映射)。
- 撤回后:资料保留,不可再领取。

### 域 5 · 创作工作台(studio.py,48KB studio.js 对应)

- **项目草稿** `projects`:`{title, aspect, clips[], captionTracks[], audioTracks[], music, copy}`;乐观并发(`updated` 字段冲突即拒);前端切页前 `captureStudioDraft()` 抢救未保存表单。
- **额度策略** `policy`:owner/每日条数/每日秒数/产品数——submit 时 `BEGIN IMMEDIATE` 扣额度。
- **配音体系**:voice 注册需 `authorized` 标记(person,provider,voiceId);subject(id/kind/name/reference)配置生成主体;request_recording 提真人录音需求(person/text/direction/due)。
- **渲染**:render_project 非阻塞(409 防重入),ffmpeg 拼接,600s 上限,产物 `render-<32hex>` 凭收据取文件(video/package zip);导出也核对实际片长。
- 已知缺陷:/api/export 的 13 个样式参数未实现(B3)。

### 域 6 · Agent 创作(文件交接模式,全项目设计最克制的一块)

**核心思想:AI 不进系统,只拿到一个自包含任务包,产物回传必须过服务端逐条校验。**

1. `package()` 产出 `orange-agent-task/v1`:`{task(含 brief/materials), instructions, resultExample}`。materials 只含**已认可且下载完成**的工作库素材(≤300 段)。
2. instructions 硬约束(原文要点):只用 materials 内素材 / 输出 JSON 不输出脚本 / 四类镜头(人物开场·产品特写·直播讲解·场景补充)之和=总片段数 / 时间不得超出原段 / 音频只引用已授权素材 ID / 必须返回 taskId+clips+reason+warnings / **"理由是待确认建议,不代表已学会"** / 不得自行生成或上传新素材。
3. `run()` 两条路线:`company`(ORANGE_AGENT_GATEWAY 网关自动执行,基线已加公网 https 守则)/`workbuddy`(人工文件交接)。状态 `ready→running→draft_ready`,异常进 `unknown` 且**禁止重复执行**需人工核对。
4. `accept()` 服务端校验:taskId 归属 / clips 1..100 / 每段 `(publicationId,segmentId)` ∈ 任务范围 ∩ 当前工作库 / 时间嵌套在原段内 → 通过才转为 studio 草稿。

### 域 7 · 成长记录(agent_growth.py,"个人经验学习"的真实落点)

- **剪辑方式** `agent_modes`:每人 3 槽,`{seconds, sellingPoints, scriptCount, shots, 四类镜头数(和=shots), name, strategy, structure}`;建 Agent 任务时按 `modeSlot` 引用。
- **轮次快照** `agent_rounds`:每项目一条不可变链 `initial→revision…→final`。规则:乐观锁(`expectedUpdated` 不匹配即拒,"草稿已在其他页面更新");快照无变化且同为 revision 则**不记空轮**;首轮必须是 initial;每轮强制 reason(≤6000 字);七键 diff(clips/字幕/音频/音乐/画幅/说明/标题)生成人类可读变更清单;**agent 来源的理由标记"待确认",人工操作标记"人工已确认"**。
- `restore()`:历史版本复制为"· 历史版本副本"新草稿并自动记一轮 initial(引用原 reason),原草稿保留。
- **意图**:不是训练个人模型,是可回溯的决策日志——每一步为什么改、谁确认的,全可审计。03 文档"不等于每人已训练独立模型"说的就是它。

### 域 8 · 音乐库(music.py)

octet-stream 导入(≤30MB,头 X-File-Name,校验失败清理不留垃圾)→ 分类打标(`music_meta` 懒建表,重构目标)→ studio 混音引用。sound-library/ 12 个音效带来源与授权说明。

### 域 9 · 桌面配对与云连接(device.py + central_client.py)

```
桌面 start(secret 只存 sha256, 配对码 300s, 限流 20/min/IP)
  → 桌面开浏览器 ?desktop=<8位码>(网页永远拿不到 deviceSecret)
  → 用户在已登录网页点确认 → approve(Cookie+CSRF+绑定校验, 拒 Bearer, 一次性)
  → 桌面 poll 每 5s(BEGIN IMMEDIATE 单赢家; 发 token 前再问 IAM 创作中心授权,
     失败先 revoke 再报错——fail-closed)
  → Bearer token(8h, 库里只存 hash)→ 之后每请求重验 IAM, 撤权即时生效
  → revoke 可主动吊销, 不可重放
```

本机侧 central_client 把会话落盘为 0600/O_NOFOLLOW/属主校验文件(README 记录的 macOS 硬化;Windows 移植需替换 os.getuid 逻辑)。另经核查补充两个 central 侧关键机制:**包交付前二次核验**(service.py:243-247,流式发 ZIP 前重跑 current_identity+binding+云端列表核对+account_key 比对,TOCTOU 防护,重构不可删)与 **operations 审计表**(所有打包/预览/下载逐条留痕);json_body 有 CL/TE 走私、重复键、NaN、精确字段集四重加固(service.py:179-195)。

### 域 10 · 剪映桥(JianyingBridge.swift)

导出 ID(正则 `^export-[a-f0-9]{32}$`)→ 从本机服务下载 `/export/<id>.mp4`(附 WebView cookie)→ AXUIElement 遍历(≤5000 节点)模拟人工:菜单"文件→导入"→ Cmd+Shift+G 填路径 → 核对素材区出现文件。无 AppleScript/URL scheme,纯辅助功能 API——脆弱(依赖中文菜单文案与剪映内部 AX 标识符,ADR 已列重构)。

**意图**:成片一键进入员工真正的工作站,同时不绕过本机授权链路(下载走本机服务带会话)。

## 5. 端到端旅程

**员工的一天**:桌面登录(配对)→ 资料中心按产品/原句/标签搜索 → 领取 → 后台校验下载(并发 1)→ 选用+备注 → 工作台建项目 → 时间轴排片段/字幕/音效/音乐 → 渲染导出 MP4/素材包 → (可选)一键导剪映 → 提真人配音需求。

**审核员的一天**:register_parsed 登记新解析 → 导入 pending-unit.json → schema 校验 → 预览听审 → 记录证据 → 发布定受众(或退回)→ 必要时撤回(不影响已领取)。

**Agent 线**:存个人剪辑方式(≤3 槽)→ 建任务(产品+风格+方式槽)→ 取任务包 JSON → company 网关执行 / WorkBuddy 人工跑 → 回传结果 → 服务端验收成草稿 → 成长记录记轮次(agent 理由待人工确认)→ 不满意可 restore 历史版本。

## 6. 设计意图与商业目的(为什么长这样)

1. **版权合规是第一约束,功能都让位于它**:不可变发布快照、撤回不追溯、逐字节校验、每包审计、解析 fail-closed;路线图上的加密预览/禁原片下载/暗水印(03 第 7 条)是同一逻辑的延伸。
2. **信任边界层层分明**:云管家持字节,中台持授权+解析+secret,员工机持已验证副本,IAM 持身份;secret 永不下放客户端;服务器至今仍代理视频字节(反模式,ADR-006 已定直连方案)。
3. **对 AI 的克制是刻意的产品决策**:文件交接、素材白名单、理由待确认、禁重复执行——"Agent 创作与成长记录界面;不代表独立模型训练已实现"(01 文档原文)。
4. **1.5→2.0 硬隔离**:18831 端口保留拒绝、数据目录禁逃逸出工程、不连旧服务不读旧源码(test_independence 守卫)。
5. **诚实边界的文档文化**:所有验证记录都写"不代表全部通过"——交接包可信度高,直接原因。

## 7. 与 04 规范的关系

本文讲"是什么、为什么";04 讲"接下来怎么改"。重构时不可破坏的不变量:§4 各域标注的校验链、状态机、审计点、fail-closed 语义——P1 路由表化与包络落地必须保留这些行为(test_local/test_central_gateway 的断言就是这些不变量的可执行形式)。
