# 历史组合去重与容量评估

状态：讨论稿 v0.11。日期：2026-11-05。关联讨论基线 v0.37 的C20–C25、C40、C58、C63–C68及D16/D17/D20。文档权威及冻结流程见[09协作规范](D:/dev/orange/docs/discovery/09_文档权威与多Agent开发协作规范.md)。本稿不是实施授权，不包含已执行性能测试或数据库变更。

## 1. 已确认与尚未确认

已确认：Fission 既要拦截同批完全相同的组合，也要拦截与历史批次完全相同的组合。任一内容组成变化即可构成新视频，包括仅替换配音或BGM；不增加相似度阈值、画面必须改变或最低变化比例。场景组顺序仍必须遵守。

另已确认：首版小组测试的新批次必须先联网完成历史查重和预占，再开始渲染；本地素材仍可不上传。该确认不是产品实施授权。

批量重复处理已确认：先自动重组，补不齐再集中引导二次编辑，不逐条弹窗；重复项和待编辑项不计入完成数量。

主动结束规则已确认：未补齐时，用户可以保留已完成结果并主动结束本批，不强制补满；完成数量按实际成功数显示。结束本批不把未完成项转成成功。

小组共享规则已确认：同一小组内共用历史去重，A已生成的组合，B也不能原样再次生成；仍按先自动重组、补不齐集中引导二次编辑处理。C25进一步确认橙子工程与成品按个人账号查看，同组仅共享判重，不互相开放成果；源素材仍按本人绑定云账号的授权访问。

已收敛：C63抽取数量和单片重复可设置；C64主动结束直接停止在途；C65合格剪映单出口完成入成功历史；C66纯编码/分辨率为再次导出；C67独立创作中心成果不入组内去重；C68转组/失去资格后资产留存、旧权限失效。待业务决定只剩后续恢复原批/另批补齐体验等；有效编辑/转换、停止竞态、指纹版本和有界搜索由工程提案。C58公司业务记录不删除，归档或删除本地导出文件不得清除成功历史或缩小已确认去重范围。

## 2. 三种身份不能混用

| 对象 | 建议计算时机 | 用途及限制 |
| --- | --- | --- |
| 源文件校验值 | 首次导入一个稳定文件版本时流式读取；版本变化后重算 | 识别字节相同的副本、核对完整性。缓存到对应版本，不每批重读整个素材库；不是业务 assetId 或使用权凭证 |
| 内容组合指纹 | 实际镜头、区间、编辑设置和音轨已确定后，视频渲染前 | 根据规范化的有效剪辑方案比较组合是否重复，是本次历史去重的主要依据 |
| 导出文件校验值 | MP4等文件生成完成后 | 文件校验、传输和产物核对；不能在渲染前得出，也不作为组合唯一性的主要依据 |

“组合之前知道结果”应表述为“规划并冻结组合后、真正渲染之前知道该方案是否已使用或已被占用”。不需要先生成视频才能发现组合重复；但也不能在选材、剪切区间和有效参数未定时完成最终判断。

如果配音是新生成的音频，需要先把音频生成并冻结，或明确采用什么稳定的业务音频身份；只哈希文字、音色和随机种子，不能代表实际生成音频的字节内容。候选规划可以提前做粗查，但最终预占必须对应实际方案。

字节hash只覆盖字节相等，重新封装、转码或另外截取出的相同画面可能得到不同hash。保留可追溯的原素材/片段来源有助于规范身份，但本方案不声称识别所有视觉相同的视频，也不引入用户未要求的感知相似度审核。

## 3. 指纹契约建议

规范输入应表达有序镜头的真实源内容引用、源区间、时间线位置和有效编辑操作，以及实际参与输出的配音、BGM、字幕等；组间顺序不能被排序成无序素材集合。业务素材标识、内容版本、文件表示和授权仍是不同概念。

规范化规则必须明确：字段顺序、缺省值、空值、时间单位、数值精度、轨道顺序及无效操作的处理。先解析随机选择，再生成指纹。批次号、任务号、路径、文件名和随机种子本身不算内容变化；不能把批次号或配方ID加入去重身份，从而让同一组合在换批次后绕过历史检查。

C66已确认仅编码或纯输出分辨率的非内容变体可再次导出，不新增混剪内容成功数。码率/封装同类归并为工程规范化建议；真正改变构图、字幕布局或音轨需按实际内容处理，不能把去重误实现为既有成果不能重新导出。

记录独立的指纹规范版本，并准备旧记录迁移或双规范比对；升级规范不能天然绕过历史。hash是检索键而非数学上的绝对无碰撞证明；保留关联的规范方案或足够的比较证据，命中异常时可核验，不将所有拒绝记录解释成肉眼完全相同。

## 4. 建议业务流程与故障语义

冻结候选方案 → 计算指纹 → 按归属空间批量检查并原子预占 → 获准条目进入有界渲染队列 → 产物校验 → 幂等确认完成并进入成功历史。

- 已确认同一小组成员共用历史。建议以统一的小组归属范围完成查询和原子预占，不按创建人、设备或批次拆开；具体字段与D07的统一所有权模型保持一致，不额外制造同义的租户层级。不同小组隔离是当前建议，不把本次确认扩展成全平台客户互相去重或泄露彼此历史。
- 不能只“查询不存在，然后开始渲染”。两台设备可能同时查不到；需要数据库唯一约束与短事务完成共享登记，冲突方重新选材或等待原任务。登记失败、超时或响应丢失都不能被当作已获准。
- 不使用无条件upsert去覆盖别人的预占或成功历史；成功记录、活动预占和执行尝试语义分开。已有任务的合法失败重试恢复同一方案，不重新抽签，也不因为自己的预占被拒绝。
- 占用关联所有者及版本/尝试凭证；凭证机制仍待验证。C40允许获准任务断网继续，本地可能仍在执行或已交付时不得只因心跳/短租约到期自动接管或释放。恢复、显式停止及完成对账须核验当前执行身份，不持有长数据库事务。
- 输出已生成但确认丢失时保留待核对状态，先对账再判断是否重做；失败不直接永久占死，也不在未核对时将其冒充成功。
- 这些控制针对业务登记与有效提交，不保证任意断网/崩溃情况下只发生一次物理计算。失联客户端可能留下额外本地文件，不能声称共享账本能阻止全部离线字节生成。

PostgreSQL可用联合唯一约束约束同一范围的重复键；冲突插入可避免覆盖已有记录。具体状态转换仍需业务设计和故障测试，不能靠数据库约束替代。依据：[PostgreSQL 17 唯一索引](https://www.postgresql.org/docs/17/indexes-unique.html)、[INSERT冲突处理](https://www.postgresql.org/docs/17/sql-insert.html)。

成功历史与各出口完成数分开：固定ResultRevision关联准入、合格产物及交付。C40已明确本地校验合格且授权有效的已准入条目无需等待云终态回执才能本地交付，联网补登记；云上传另依网络和人工确认。C65合格剪映单出口完成也进入成功历史，不能拿未完成工程或普通ZIP充数；已有合格结果不因后续出口失败/标签待核对/主动停止而释放。视频和剪映按类型计数，不混编辑前视频与编辑后草稿。

### 4.1 重复后的自动重组与二次编辑

已确认的产品顺序是先自动重组，仍未补齐目标数量时集中引导二次编辑，不逐条弹窗；重复项、待编辑项不计入完成数量。

建议执行边界如下：

- 对准入前已判重复的候选，记录判定后生成新的候选方案，保持配方允许的组间顺序、选材范围及授权；再次查重和预占，不渲染被拒绝的重复方案。
- 自动重组应有候选次数或耗时等预算，具体阈值待决定。达到预算仍未补齐时，集中展示缺口与可编辑项；若未穷举证明，就不能宣称“所有组合已用尽”。连接异常或预占响应不明也不能冒充“组合耗尽”，应按准入与恢复规则处理。
- 重复碰撞次数是选材尝试量，不是新增结果数。一条目标结果遇到多次重复，不能因此增加多个待编辑缺口。
- 二次编辑衔接有权访问的完整剪辑方案和素材；同组共享历史已由C24确认，但命中其他成员的历史组合不自动授予查看、复制或编辑其工程的权限。工程/成品个人可见已由C25确认；素材授权与审核/管理权限按D07/D10继续讨论。
- 若编辑结果用于补齐本批新视频，建议保留与原批次及待补结果的关联，以修改后的冻结修订重新查重、预占；成功满足该结果交付要求后再计入完成。不能因为打开编辑器、保存工程或生成了新修订就算完成，也不因此把所有独立编辑器导出强制纳入此流程。
- 编辑不覆盖历史成功方案；“深度二次编辑”不是最低差异要求。按已确认规则，仅替换一个镜头、配音或BGM也可以形成新组合。
- 自动重组与失败重试分开：前者改变尚未获准的候选，后者恢复已获准结果的原冻结方案，不随机换素材掩盖失败。

完成数依据真实合格结果，不按候选、尝试或保存的工程数量计算。目标100、合格80、待编辑20仍为80/100。C65下合格剪映单出口可登记相应完成及成功历史，但不冒充视频完成；同一内容视频/剪映均交付不重复累计原批结果。重复、待编辑、失败、在途均不算完成，同一结果重试幂等。

### 4.2 保留成功结果并主动结束本批

已确认：未补齐目标数量时，允许用户保留已完成结果并主动结束本批，不强制补满；完成数量按实际成功数显示。该操作必须来自用户的主动选择，不能在自动重组未补齐时擅自替用户结束。

以目标100条、80条成功、20条未完成且无在途任务为例：结束后保留80条成功结果，实际完成数为80，原目标仍为100；余下20条不再要求本批必须补齐，也不计为成功。任务不应继续显示为强制等待补足，但“已结束”不等于“100条全部成功”。具体状态枚举和呈现方式尚未定稿。

工程建议：结束动作保持幂等，保留原目标、实际成功数、操作者、时间和未完成项状态。成功产物及其历史组合登记不因结束而删除；重复结束请求不能使成功计数增加或清零。结束本批也不代表用户主动删除待编辑工程，其保留与清理规则另行决定。

C64已确认结束时停止派发并直接停止在途处理，不选择默认允许跑完。工程须发出有界取消、验证worker实际退出、隔离未完成临时文件，按取消与合格提交的权威先后核对迟到结果；状态未知先对账，不能立刻腾空仍可能已交付的占用。已完成结果保留。重开原批或关联新批补齐尚待用户体验决定，不自动补满；转组/失去资格按C68保留数据而不保留旧权限。

## 5. 对本机与数据库的压力

这是新增成本，但合理实现下应远小于把重复视频渲染完再丢弃的成本。此结论是架构预期，尚未压测，不能承诺特定机器或云套餐的延迟与并发。

| 成本 | 主要影响因素 | 控制方法建议 |
| --- | --- | --- |
| 源文件校验 | 首次需要读完文件；读盘量与源素材总字节数相关 | 流式处理、限制并发、稳定版本缓存；检测使用期间文件改变，不只信任路径或修改时间 |
| 方案指纹 | 规范方案大小、字段规范化和候选数量 | 处理小型结构化方案，不读取全部成品或解码整段视频 |
| 历史查询与登记 | 历史总量、并发请求、索引与网络 | 索引查询、批量请求、短事务；不把全部历史下载到客户端逐条扫描 |
| 重新选材 | 可用组合剩余比例、约束复杂度 | 有界候选生成；接近耗尽时提示不足或待进一步搜索，不擅自变更内容规则凑数 |
| 长期存储 | 组合数量、冻结方案大小、索引、审计与备份 | 最小去重账本和详细日志分层，明确保留规则；按实际数据库体积评估 |

SHA-256二进制摘要每条32字节；100万条仅摘要负载为32,000,000字节，约32MB（十进制）。这不是数据库总容量：行结构、空间与任务标识、状态、索引、规范方案、执行记录、审计和备份均另计。若使用64字符十六进制文本，连摘要本身的存储方式也不同。

每批10/50/100条不是主要容量上限，更重要的是历史累计量、同一时段请求量及重复候选比例。不得预先展开并保存A×B×…×N全部理论组合；只为请求数量生成有界候选并登记活动或成功结果。随机重试失败不等于已经证明全部组合耗尽。

首版建议先利用已有PostgreSQL，不为精确组合判重额外引入向量库或相似度平台；是否需要其他缓存依据测量再决定。

## 6. 联网、权限与本地素材

本地素材可不上传视频内容。为实现已确认的同一小组跨成员共享去重，需要同步最小必要的组合指纹、预占状态等元数据，不能只查询当前用户或当前电脑的历史。指纹和使用历史也可能涉及用户隐私，需受控权限、限量查询与明确保留规则，不等同公开共享。

离线本地缓存只能保证已同步历史与本机范围，不能知道另一台离线设备刚做了什么。Ethan已确认首版小组测试：新批次必须先联网完成历史查重和预占，再开始渲染。查重/预占失败或结果不明时，不能把条目按已获准执行。

C40已确认：已准入且依赖齐全、授权有效的任务，断网继续本地执行和交付，联网后补登记；不能新增终态必须联网才能取得本地产物的门槛。工程需据此设计持久占用与幂等对账：不能只因心跳/短租约到期就把可能仍在执行或已交付的组合释放给别人。续期、长期失联、取消/撤权、重新连接及恢复规则仍需验证；仅启动时联网本身不是严格互斥的充分证据。新组合仍遵守C21，云上传和云模型等在线动作仍等待网络。本地能力不要求视频内容或全部元数据上传；成员资格变化和多组权限按C68处理，独立创作成果按C67排除；D17只继续收敛原判重域映射、占用与恢复等工程机制。

云端命令核验成员权限与空间归属，数据库适用RLS及明确授权；普通客户端不能改写别人的历史或直接宣告成功。纯本地文件未上传时，服务端无法独立证明用户上报的hash确实对应真实媒体，不能把组合去重宣传成恶意客户端防作弊或版权证明。权限设计参考：[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。

### 6.1 小组判重与内容访问分开

已确认：同一小组成员共用历史查重结果，A已生成的组合会约束B新建相同组合。该规则不能通过更换创建人、设备或批次号绕过；在线共享登记仍须覆盖并发预占，而非只有A成功后的查询。

建议由可信端根据当前成员资格和任务归属核定小组范围，不能仅信任客户端上报的小组标识。统一契约需要表达小组归属和操作者这两个不同含义，但字段名、资源所有权和多组切换方式尚未定稿。

去重命中是业务判定，不是资源读取授权。工程和成品的列表、直链及下载按本人归属校验，源素材另按本人使用授权；没有权限时，不因命中另一成员的历史而返回其文件路径、可编辑时间线或下载地址。集中二次编辑应使用当前用户有权访问的候选方案和素材，而非自动复制命中的历史工程。

不同小组间隔离、不做全平台判重仍为工程建议；C67明确独立创作中心成果不登记混剪历史。C68明确组资格失效后数据留存但旧组权限不延续，多组逐一核验。工程建议任务固定原判重域、历史留在原组而不随操作者转组搬走；具体映射和恢复须验证，不把留存或历史命中当访问许可。

### 6.2 独立账号与历史去重迁移

新版采用独立橙子账号，再绑定本人云管家；旧百橙账号和历史资料需保留可核对的迁移关系。更换认证身份不能清空或拆散已经存在的小组去重记录，也不应把别人的历史登记到当前登录者名下。

建议分别迁移个人归属、组内去重范围与供应商绑定，保留旧身份来源和指纹规范版本。对能够证明原组合及来源的历史记录才建立相应映射；仅有旧MP4但缺少真实选材/剪辑方案时，保留成品与来源缺口，不能把成品文件hash冒充组合指纹，也不能宣称已覆盖全部旧组合。具体数据范围与恢复方式由D18决定。 C77明确缺关键身份/方案/文件或许可而无法核验的历史内容隔离不可用；缺口保留待补齐，不虚构组合去重覆盖或删记录。
